### 2. 已定位并修复 WS/HTTP 来回切换根因

问题不在 1 秒心跳本身，而在前端切换策略：

- 交易时心跳改为 `1000ms`
- `websocket.ts` 的 stale 阈值变成 `1000 * 2 + 1500 = 3500ms`
- 但重连退避仍然是 `1000 / 2000 / 5000 / 10000ms`

结果就是：

1. WS 断一下
2. 前端刚准备重连
3. stale 监视器先把状态打成 `fallback`
4. UI 和 DataLoader 又切去 HTTP
5. WS 一恢复又切回 TDX

这就是你昨天和今天都看到的“订阅和轮询不停切换”。

### 4. `TC_SetL2UserInfo` 新发现

2026-04-27 这轮继续下探后，多了三个确定结论：

1. `probe-tc-setl2-matrix` 已经补齐并可运行  
   `tools/TdxL2Helper/Program.cs` 现在支持：
   - `probe-tc-setl2-matrix`
   - `direct-cli` candidate
   - `probe-tc-setl2` 的完整 pre/post LoginRet / RightInfo / L2Info 采样

2. `SAVEZH` 不是 `L2ZH`  
   本机 `D:\APP_SOFT\TDX\T0002\usercomm.ini` 中：
   - `SAVEZH=1`

   这更像持久化开关，不是业务态 `L2ZH`。helper 里原先把 `SAVEZH` 镜像成 `L2ZH` 的假设已经删掉。

3. 运行中 `tdxw.exe` 的 `0x011D4FEC` 当前值确认为 live `L2ZH`  
   对 `tdxw.exe` PID `18796` 的只读内存采样显示：
   - `0x011D4FEC = tdxPC1891093`
   - 长度 `12`

   这和 `datacache.json` 里的 `TDXID=R210304...` 形态明显不同，因此 `0x011D4FEC` 不应再叫 `tdxid_string_object`。

4. helper 已自动接入 live `L2ZH`  
   `LoadCachedLoginMaterials()` 现在会：
   - 查找当前 `TDX root` 下运行中的 `tdxw.exe`
   - 只读读取 `0x011D4FEC`
   - 把结果以 `L2ZH` 材料并入 matrix

   实测 `probe-tc-setl2-matrix --profile-filter l2zh` 已能自动选出：
   - `citicscfv-l2zh-*`
   - `l2zh-citicscfv-*`

   不再需要每次手工 `--setl2-arg2 tdxPC1891093`

### 5. 当前 `setl2` 试验结论

基于 live `L2ZH=tdxPC1891093` 做了两组动态验证：

1. 不带 login 前置  
   - `CITICS#CFV + live L2ZH + {empty|ConnectQSID|JYMainQSID|OID}`
   - 以及 `arg1/arg2` 对调
   - 8 组都能稳定打出 `TC_SetL2UserInfo returnValue = 1`
   - 但 `RightInfo / L2Info` 仍然全空，没有真实权限态变化

2. 带 cached login 前置  
   - `TC_Login / TC_Login2` 仍会落到 `SEHException` 或直接 `0xC0000005`
   - 这说明当前 blocker 还是登录链路，不是 `TC_SetL2UserInfo` 的函数壳子

这轮可以确认一件事：

- `TC_SetL2UserInfo returnValue = 1` 只说明参数形态被接受，不能说明十档/L2 权限态已经建立。
