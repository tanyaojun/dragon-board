# THSBigOrder 会话日期选择设计

## 目标

在 `tools/THSBigOrder` 顶部数据源右侧增加日期控件。用户选择的交易日期统一控制白色分钟线、蓝色大单均线、红绿大单点和右侧大单列表，彻底禁止跨交易日叠加。

顶部现价、换手、量比等行情指标仍显示当前值，不切换为历史行情。

## 界面与交互

- 使用紧凑的 WinForms `DateTimePicker`，格式为 `yyyy/MM/dd`，默认值和最大值均为当天。
- 日期控件放在数据源下拉框右侧，即用户截图红框位置。
- 日期、股票代码或数据源变化时，取消旧请求、清空旧图层和列表，再发起新请求。
- 选择非交易日时，使用 `mootdx` 提供的上交所交易日历解析最近一个交易日，并把控件更新为实际会话日期。
- 不维护或硬编码周末、节假日规则。交易日历不可用时不猜测日期。
- 历史日期进入历史查看模式：暂停自动刷新和语音播报，并禁用对应控件；切回当天后恢复用户原有选择。

## 请求与数据流

使用请求级的 `stockCode + requestedDate`，不把日期放进 Provider 的共享可变状态，避免快速切换时发生串单。

1. `python-bridge` 通过 `mootdx` 上交所交易日历把 `requestedDate` 解析为有效 `sessionDate`。
2. 会话确定后，大单、分钟线、当前行情和涨停信息并行加载。
3. “龙虎大单”和“THS大单”都显式携带 `sessionDate`，按各自现有接口分页拉取完整数据。
4. 分页缓存键包含 `sessionDate`，当天与历史缓存互不复用。
5. 分钟接口显式携带日期：当天交易时段调用 `mootdx.minute()`；历史会话调用 `mootdx.minutes(date=...)`。
6. 图表和列表仅绑定与 `sessionDate` 一致的大单、均线和分钟数据。

## 数据一致性与失败处理

- 每个大单分页结果和分钟结果都必须校验实际会话日期。
- 上游返回其他日期时整批拒绝，不允许按相同时分把旧订单贴到新分钟线。
- 所选日期无大单时，空列表是有效结果。
- 历史模式只允许回退同一 `sessionDate` 的缓存。
- 交易日历不可用时清空历史图层并显示“交易日历不可用”。
- 上游日期不一致时显示“数据日期不匹配”，不静默降级到其他日期。
- 旧请求晚返回时不得覆盖当前股票、数据源和日期对应的界面。
- 图表层继续保留同日校验，作为数据提供层之外的最后防线。

## 验证

- C# 测试：默认今天、非交易日回退、双数据源日期参数与分页、跨日拒绝、请求竞态、历史模式停自动刷新和语音、切回今天恢复。
- Python 测试：上交所交易日历解析、当天实时分钟、指定历史日期分钟、无日历时结构化失败。
- 代理测试：日期参数透传、分页缓存按日期隔离、返回会话日期校验。
- 构建：`dotnet build tools\THSBigOrder\THSBigOrder.csproj -c Release`。
- 窗口验收：核对控件位置，并确认白线、蓝线、红绿点和列表始终属于控件显示的同一日期。

## 非目标

- 不新增历史 K 线、历史顶部行情或回测能力。
- 不修改现有大单识别算法、金额过滤和红绿含义。
- 不硬编码交易日、周末或节假日列表。
