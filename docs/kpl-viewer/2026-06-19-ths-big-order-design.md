# THSBigOrder 整体升级设计

## 1. 目标

把现有 `tools/KPLViewer` 升级并完整重命名为 `tools/THSBigOrder`，替换失效的 KPL 大单数据源，并按参考图升级为高密度大单监控终端。运行时优先由桌面端直连新浪、腾讯和同花顺公开接口；对应直连失败时，才独立降级到本地 `proxy-server`，不再把 3000 端口作为启动前提。

成功标准：

- 目录、项目、程序集、命名空间和可执行文件统一为 `THSBigOrder`，窗口标题和产品名统一为“THS大单监控”。
- 大单明细和主力汇总来自同花顺，基础行情和分时量价来自腾讯，涨停上下文来自同花顺涨停池；各来源均为直连优先、对应代理路由降级。
- 不再请求东方财富，也不改变 Dragon Board 现有 KPL 大单接口的语义。
- 主界面具备顶部行情、双侧价格/涨幅坐标、四小时主图网格、资金趋势、贴合分钟价格线的主动买卖事件点、分钟大单柱、八段 30 分钟成交统计和右侧明细。
- 数据源失败时有明确状态，不把缺失、陈旧或估算数据展示为实时精确数据。

## 2. 非目标

- 本期不实现竞价采样、竞价弱转强或竞价历史回放。
- 不实现真实 L2 十档、逐笔委托、完整盘口队列或盘口级封单变化。
- 不复刻参考软件未公开的私有指标公式。
- 不移除或改变现有 `/api/big-order/main-monitor`、`/api/big-order/all-day` KPL 兼容路由。
- 不引入大型图表框架或新的 UI 技术栈。

## 4. 数据架构

THSBigOrder 保持 `IMarketSnapshotProvider` 作为界面侧唯一数据门面。每次刷新并行加载四类数据；每一类先请求公开上游，只有该类直连出现网络错误、超时、无法解析或合同结构无效时，才请求其对应的 `http://127.0.0.1:3000` 代理路由：

1. 同花顺大单明细直连接口；降级路由为 `GET /api/big-order/ths-detail?stockCode=xxxxxx`。
   - 上游：同花顺 `mainMonitorDetail`，请求携带固定浏览器 User-Agent、Referer 和 JSON Accept。
   - 提供：`title`、`list`、`pricechange`。
   - 用途：大单明细、名称、现价、涨幅、主买、主卖和分时涨幅。
2. 腾讯基础行情直连接口；降级使用 proxy-server 现有腾讯基础行情路由 `GET /api/quotes/tencent?codes=xxxxxx`。
   - 提供：股票名称、现价、涨幅、成交量、成交额、换手率和量比。
   - 腾讯响应按 GBK/GB2312 正确解码；成交额按 `现价 × 成交量 × 100` 估算，无法计算时显示 `-`。换手率来自 `f8`，量比来自 `f10`；涨停池包含当前股票时，`turnover_rate` 可作为换手率补充来源。
3. 腾讯个股分时直连接口；降级路由为 `GET /api/quotes/tencent/minute?code=xxxxxx`。
   - 上游：腾讯个股分时接口 `https://web.ifzq.gtimg.cn/appstock/app/minute/query?code={market}{code}`。
   - 提供：交易日内每分钟的时间、价格、累计成交量和累计成交额。
   - 用途：按相邻分钟累计成交额差分得到单分钟成交额，再汇总为该股票八个 30 分钟区间的全部成交额。
   - 午休后的首分钟使用 `13:00` 累计值减去 `11:30` 累计值；首个 `09:30` 分钟使用其累计值减零。若分钟数据从日中截断开始，首个点只作为累计基准，不把未知历史累计额回填到该区间。负差值、非有限值和时间乱序点视为无效数据，不写入统计。
4. 同花顺涨停池直连接口；降级路由为 `GET /api/limitup/10jqka`。
   - 提供：封单额、封单量、开板次数、首次/最后涨停时间、连板高度、封板成功率、换手率、涨停类型和原因。
   - 当今日涨停池为空且当前股票无记录时，客户端继续向前查询最近 7 个自然日，优先使用最近一个包含当前股票或包含有效涨停池数据的日期；仍无当前股票记录才表示“非涨停池”，不是错误。

基础行情和分时量价固定使用腾讯，不接入 `python-bridge`，也不使用东方财富。腾讯分钟接口能一次返回当日完整分钟历史，程序中途启动也可补齐此前区间；`python-bridge` 当前只提供订阅后的实时 L1 快照，不能完整替代分钟历史。

四类数据独立降级：例如同花顺大单直连失败时，只把大单明细切到代理，不强制腾讯基础行情、腾讯分时和同花顺涨停池一起切换。涨停池先按最近交易数据回退查询；合法空结果不触发降级，最终仍不含当前股票时解释为“非涨停池”。

桌面端按来源拆分轻量适配器，分别负责请求、解码、合同校验和规范化；`THSBigOrderDataProvider` 只负责编排并合并统一读模型，不把所有上游解析继续堆入单一大类。直连和代理响应都转换为同一业务模型，不伪装成另一种 envelope。

### 4.1 既有代理降级路由

`/api/big-order/ths-detail`、腾讯基础行情路由、`/api/quotes/tencent/minute` 和 `/api/limitup/10jqka` 均已由前期升级提供。本轮只把它们从唯一入口调整为对应直连来源的降级入口，不新增或改变代理合同。

`/api/big-order/ths-detail` 路由职责：

- 校验 `stockCode` 为六位数字。
- 以 GET 请求访问 `https://vaserviece.10jqka.com.cn/Level2/index.php?op=mainMonitorDetail&stockcode={stockCode}`，并使用固定的浏览器 User-Agent、Referer 和 JSON Accept 请求头。
- 校验上游 `errorcode`、`title` 和 `list` 基本结构。
- 按股票代码使用进程内短 TTL read-through 缓存，并允许短时间 stale fallback；此能力不依赖 Redis，代理重启后缓存自然清空。
- 缓存 value 保存真实 `fetchedAt`，每次响应另写 `servedAt`；客户端陈旧提示必须使用 `fetchedAt`。
- 返回结构化来源和缓存元信息；上游失败且无 stale 时返回 HTTP 200 degraded envelope（`ok=false/degraded=true/errorCode/data`）。

`/api/quotes/tencent/minute` 路由职责：

- 校验 `code` 为六位数字，并按沪深代码生成 `shxxxxxx` 或 `szxxxxxx`。
- 校验腾讯返回 `code=0` 以及目标股票的分钟数组结构。
- 把每行 `HHmm price cumulativeVolume cumulativeAmount` 规范化为结构化分钟点，不把腾讯原始字符串格式扩散到桌面端。
- 使用进程内短 TTL read-through 缓存和短时间 stale fallback；上游失败且无 stale 时返回 HTTP 200 degraded envelope。

`/api/limitup/10jqka` 使用同一进程内短 TTL 缓存，但保持现有响应主体兼容。腾讯基础行情和腾讯个股分时分别使用独立缓存键。

### 4.2 客户端读模型

`THSBigOrderDataProvider` 把四路响应合并为一次不可变刷新快照：

- `StockSummary`：代码、名称、现价、涨幅、换手、量比、成交额。
- `MainFundSummary`：主买、主卖、净额、大单笔数。
- `LimitUpContext`：是否在池、封单、开板、连板、原因和时间；封板率和最后涨停时间保留在数据层，不在顶部指标区展示。
- `BigOrderItem[]`：时间、金额、手数、成交价、四类性质和既有信号标记。
- `PricePoint[]`：同花顺分钟涨幅序列，仅保留为腾讯分钟价格缺失时的兜底。
- `MinuteTurnoverPoint[]`：腾讯分钟价格、累计成交量和累计成交额，用于计算全成交均价、每分钟成交额及每 30 分钟的该股票全部成交额。
- 图表聚合序列：由腾讯分钟量价生成全成交均价线，由同花顺大单成交价和手数生成大单成交均价线；两条线均为价格量纲。

四类性质映射固定为：

| 同花顺性质 | THSBigOrder 类型 |
| --- | --- |
| 主力主买 | 主动买 |
| 主力被买 | 被动买 |
| 主力主卖 | 主动卖 |
| 主力被卖 | 被动卖 |

## 5. 刷新、降级和错误状态

- 默认每 6 秒刷新一次，手工刷新沿用同一流程。
- 同一时刻只允许一个刷新任务；同股票的定时重入直接跳过。切换股票时取消旧请求、递增请求代次并排队刷新最新代码，旧响应到达后必须因代码或代次不匹配而丢弃。
- 四路请求并行执行，分别记录 `Direct`、`ProxyFallback`、`Stale`、`Missing` 和 `Failed` 状态。
- 直连使用短超时；直连失败后只调用该来源对应的代理路由。直连与代理都失败时，才允许回退同一股票最后一次成功快照；禁止跨股票使用陈旧数据。
- 同花顺大单失败时保留最后一次成功快照，并在界面显示“数据陈旧”和最后更新时间。
- 腾讯基础行情失败时涨幅、换手、量比和当日成交额显示 `-`，不阻断大单列表；涨停池有当前股票记录时，可作为换手率的补充来源。
- 腾讯分钟分时失败时底部“成交总额”一行显示 `-`；大单 30 分钟汇总仍由同花顺大单明细独立计算。
- 涨停池成功但无代码时显示“非涨停池”；请求失败时显示“涨停数据不可用”。
- `proxy-server` 不在线不影响已成功的直连来源；只有某来源直连失败且对应代理也不可用时，该来源才进入 stale、missing 或 failed。界面使用“直连”“代理降级”“数据陈旧”“数据不可用”等简洁状态，不再把整个应用概括为“代理不可用”。
- 切换股票代码后不得显示上一只股票的缓存；只有代码一致的 stale 快照可以回退。
- 客户端分别解析直连原始合同与 proxy envelope，再归一化为业务数据；HTTP 200 degraded、合法空列表和网络连接失败是三个不同状态。

## 6. 界面设计

界面保持 WinForms 高密度暗色终端风格，并使用双缓冲自绘降低闪烁。

### 6.1 顶部信息区

分为三组：

- 股票行情：名称、代码、现价、涨幅、换手、量比、成交额。
- 主力资金：主买、主卖、净额和大单笔数。
- 涨停上下文：封单额、开板次数、连板高度、封板成功率和涨停原因摘要。

保留现有股票代码输入、通达信跟随、锁定、置顶、自动刷新、语音和分析入口。

程序图标只使用项目内 `icon.ico`，不再从外部网站下载；运行时外部 HTTP 请求仅限本设计列出的新浪、腾讯和同花顺行情接口，以及失败后的本地代理降级请求。

### 6.2 左侧图表区

新增一个专用双缓冲 `BigOrderChartControl`，同一时间轴分层绘制：

- 主图：白线为腾讯分钟价格线；蓝线为同花顺大单累计成交均价，按时间顺序计算 `Σ(大单成交价 × 大单手数) / Σ(大单手数)`；黄线为腾讯全成交累计均价，计算 `累计成交额 / (累计成交量（手）×100)`。三条线共用价格量纲，不允许独立按各自最小/最大值铺满主图。
- 主图区左侧预留价格轴，右侧预留对应涨跌幅轴；两侧标签共用同一水平网格，以新浪昨收价建立价格/涨幅映射。纵轴范围必须包含 `0%` 和两条均价线的全部有效值，向上下各留 5% 视觉余量；有效范围不足 `2%` 时按 `2%` 展开。新浪昨收不可用时，允许由现价和当前涨幅反推；两者均不可用时右侧涨幅轴显示 `-`，左侧仍按有效价格范围绘制。
- 主图区把 240 个交易分钟压缩为连续时间轴，并在 `09:30 / 10:30 / 11:30-13:00 / 14:00 / 15:00` 处绘制边界，形成四个一小时竖格；午休不占横向宽度。
- 不再把累计大单净额作为白线叠加到价格主图；资金值和价格量纲不同，独立缩放会制造不可比较的视觉高低。本轮不新增资金副图。
- 大单事件点：白色分钟价格线绘制完成后，在该线上按每笔大单的精确秒级时间叠加圆点。仅 `主力主买（Type=2）` 绘制红点、`主力主卖（Type=4）` 绘制绿点；被动买卖不绘制，且不存在白色圆点。
- 每一笔符合条件的大单对应一个圆点，不按同秒、同价或相邻像素合并。圆点使用固定尺寸和暗色描边，不按金额缩放，避免大单密集时进一步遮挡白线。
- 圆点纵坐标不是该笔成交价，也不是大单累计均价；优先使用同一时刻最近的腾讯分钟价格百分比，因此圆心贴合白色分钟线。分钟线缺失时才回退到该笔纳入后的大单累计均价。聚合器为每笔有效大单生成 `时间、累计均价、金额、性质` 事件点；同秒多笔仍保留各自事件和顺序。
- 圆点与右侧过滤完全联动：金额按钮使用与明细列表相同的“大于等于阈值”口径；“全部”显示红绿两类，“买盘”只显示红点，“卖盘”只显示绿点。点火、砸盘、买活跃、承接好等特殊筛选不额外改变圆点集合。
- 彻底删除现有固定在主图顶部/底部的旧红绿信号点及其图表绘制/聚合入口，不与新的白线事件点并存，避免同一颜色同时表达两套位置语义。`FundMarker`、`BuyMarker` 及其点火、砸盘、买活跃、承接好计算仍由右侧明细、特殊筛选、统计和语音使用，因此不删除这些业务字段与计算。
- 分钟柱：按分钟聚合同花顺大单列表的买卖手数；明确属于“大单样本”，不是全市场完整成交量。
- 底部统计：完全替换原 30、50、100、300、500、700、1000 万阈值热力图，按 `09:30-10:00`、`10:00-10:30`、`10:30-11:00`、`11:00-11:30`、`13:00-13:30`、`13:30-14:00`、`14:00-14:30`、`14:30-15:00` 划分八格。区间统一为左闭右开；腾讯分时中的上午收盘点 `11:30` 计入第四格，全天收盘点 `15:00` 计入第八格，避免收盘分钟成交遗漏。
- 八格分两层：第一层为该股票在对应 30 分钟内的全部成交额，来自腾讯分钟累计成交额差分；第二层为对应时段内同花顺大单的成交总额，固定为买盘大单额加卖盘大单额，不使用净额。
- 每层在自身八个区间内独立归一化：本层最大金额为 100%，其它格按 `金额 / 本层最大金额` 计算填充比例。色块从左向右填充，并随比例提高亮度；第一层使用红色热力，第二层使用灰白到粉红热力。两层不得共用最大值，避免总成交额数量级压制大单层。
- 每格金额文本继续居中显示并保持高对比度；金额为 `0` 时只显示暗底和 `0`，数据缺失显示 `-` 且不绘制热力。未来区间的 `0` 不参与最大值计算。
- 已发生但无成交的区间显示 `0`，尚未发生的区间显示 `0`；数据源缺失或解析失败显示 `-`。右侧金额筛选按钮继续保留，仅不再充当底部图表维度。

图表不展示无可靠公式的“趋势拉升”等私有指标名称。

### 6.3 右侧明细区

- 保留时间、金额、手数、均价、买卖性质、资金标记和买盘标记。
- 增加“全部 / 买盘 / 卖盘”切换，替代无真实第二来源的“渠1 / 渠2”。
- 保留金额筛选、颜色语义、排序、滚动和语音触发。
- 数据源陈旧时列表仍可查看，但标题区持续显示陈旧状态。
- 金额按钮或“全部 / 买盘 / 卖盘”切换后，列表、统计和分钟线圆点在同一次 UI 更新中同步刷新，不重新请求网络数据。

### 6.4 响应式桌面布局

- 默认 1280×800，左侧图表约占 72%，右侧明细约占 28%，最小窗口为 960×640。
- 宽度低于 1100 时隐藏完整涨停原因，只保留“查看原因”提示；低于 1020 时再隐藏封板成功率和最后涨停时间。窗口恢复后字段自动恢复。
- 使用 net48 应用 manifest 声明 PerMonitorV2/PerMonitor DPI awareness；字体、线宽和控件尺寸按 DPI 缩放，并验证运行中跨显示器切换。

## 7. 测试与验收

### 7.1 代理测试

- 股票代码校验。
- 同花顺成功响应透传/规范化。
- 空列表、上游错误码、结构缺失和超时。
- 缓存命中、并发请求合并和 stale fallback。
- 旧 KPL 路由回归测试，证明语义未改变。
- 腾讯分钟接口的代码校验、沪深市场映射、累计成交额解析、空数组、结构错误、缓存命中和 stale fallback。
- 代理测试继续证明降级路由合同稳定；桌面端直连改造不删除既有代理路由。

### 7.2 C# 测试

- 四类成交性质映射。
- 手数、金额、百分比、逗号价格和日期时间解析。
