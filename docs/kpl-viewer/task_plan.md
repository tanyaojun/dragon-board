# KPLViewer 整体升级分析计划

## 目标

评估参考截图中的功能在 `tools/KPLViewer` 与同花顺现有数据合同下能实现多少，并形成可分阶段验收的升级设计。

## 阶段

- [x] 调查现有 KPLViewer 数据流与同花顺接口
- [x] 核对同花顺网页版实现和字段口径
- [x] 对照目标截图拆解界面、图表、指标和交互
- [x] 盘点现有数据可直接支持、可推导、缺失的能力
- [x] 给出 2-3 个升级范围方案并确认
- [x] 输出经用户确认的设计规格
- [x] 编写可执行实施计划并完成主代理自审
- [x] 完成两位 subagent 交叉评审并修复文档
- [x] 用户要求继续，进入计划执行

## 成功标准

- 每个目标模块标注“可直接实现 / 可近似实现 / 需新增数据源 / 当前不可实现”。
- 明确成交额、换手、量比及图表指标的数据口径。
- 不在设计确认前修改生产代码。

## 已知风险

- `tools/KPLViewer` 当前整体为未跟踪目录。
- 同花顺 `mainMonitorDetail` 不提供换手、量比和完整市场成交额。
- `.superpowers/` 当前未被 `.gitignore` 忽略，视觉辅助产物不能纳入业务提交。

## 已确认范围

- 不实现竞价采样和竞价弱转强。
- 桌面工具允许依赖本地 `proxy-server`。
- 原 `tools/KPLViewer` 整体升级并重命名为 `tools/THSBigOrder`。
- 代理采用“新增同花顺专用路由 + 复用腾讯行情和同花顺涨停池”方案；不改变现有 KPL 大单接口语义。

## 错误记录

- Web 搜索与直接打开接口遇到 403；已改用本机带请求头的只读请求验证。
- Windows Bash 启动器不可用；已改为直接运行同一 Node 视觉服务。
- 更新规划记录时首次补丁上下文不匹配，随后 PowerShell 通配符未被 `rg` 接受；已改为对目录执行 `rg` 后使用准确上下文。
- 实施计划自审时再次使用了 PowerShell 不支持的 Bash brace expansion；已改为显式列出两个文档路径。
- 两位新 subagent 的最终零问题复核因账户额度限制未启动；此前两位 reviewer 已完成两轮有效评审，主代理修复第二轮剩余问题并重新执行静态自审。
