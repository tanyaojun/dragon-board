# 真龙复盘案例回放模板

## 1. 这份文档干什么

这份文档不是讲代码，而是讲怎么把一天的盘面回放成真龙模块能理解的语言。

目标是让你在复盘时，用统一模板记录这四类样本：

- 真龙
- 高标
- 热度票
- 伪龙

还有一条前提：

- 盘中记录现象
- 收盘以后再下最终真龙结论

如果当日日级快照和收盘态还没落下来，不要急着把某只票写成“今日真龙”。


## 2. 通用回放模板

每个样本建议至少记录下面这些字段。

### 2.1 基础信息

- 交易日
- 股票名称
- 股票代码
- 所属题材
- 所属战场
- 当日角色
- 当日 `authority`

### 2.2 战场背景

- 题材热度
- 主线持续天数
- 联动性
- 题材涨停数
- 资金承接
- 战场主导性

### 2.3 盘中轨迹

- 首次强势时间
- 早段排位
- 中段排位
- 尾段排位
- 是否带出 follower
- 是否经历分歧
- 收盘是否仍领先

### 2.4 结果结论

- 通过了哪些门
- 没过哪些门
- duel 胜负
- `tradeability`
- `chaseRisk`
- 最终归类在哪个榜

## 2.5 盘中记录和收盘确认要分开写

这是复盘质量最容易掉下去的地方。

推荐把一天拆成两层记录：

### 盘中观察层

只记录事实，不下最终龙头结论。

建议记录：

- 哪个战场在升温
- 谁先动
- 谁带出跟风
- 谁只是被热度抬上去
- 谁到了尾段开始失位

盘中结论允许写：

- “像龙”
- “高标样本”
- “热度样本”
- “候选待确认”

盘中结论不要写：

- “已经确认市场总龙头”
- “今天唯一真龙就是它”

### 收盘确认层

等这些数据齐了再下结论：

- `close frame`
- 日级快照
- 当天 `reviewCompleteness`

收盘后才确认：

- `authority`
- `role`
- 是否进入 `trueLeaders`
- 是否只是 `heightBoard / attentionBoard`

## 2.6 一页式快检清单

在写最终结论前，先问自己 6 个问题：

1. 今天的主战场到底是什么
2. 这只票是发动原因，还是热度结果
3. 它有没有带出 follower
4. 它有没有经历分歧
5. 它收盘有没有守住领导权
6. 当前结论是盘中观察，还是收盘确认


## 3. 真龙回放模板

### 3.1 判定目标

回放时要回答：

1. 它是不是发动者
2. 它有没有带动战场
3. 它有没有穿越分歧
4. 它收盘还有没有领导权

### 3.2 模板

```text
【真龙样本】
交易日：
股票：
代码：
题材：
战场：

一、战场背景
- 题材热度：
- 主线持续：
- 联动性：
- 涨停扩散：
- 战场主导性：

二、盘中轨迹
- 首次强势时间：
- 早段位置：
- 中段位置：
- 尾段位置：
- follower 增量：
- 题材热度变化：

三、四道门
- 战场门：
- 因果门：
- 分歧门：
- 收盘门：

四、duel
- initiative：
- height：
- acceptance：
- capitalRecognition：
- carryEffect：
- segmentPersistence：
- closeIntegrity：

五、结论
- authority：
- role：
- tradeability：
- chaseRisk：
- 为什么它是真龙：
```

### 3.3 收盘后再补的一行

建议每个真龙样本最后再补一句：

```text
六、确认条件
- 当日日级快照：已保存 / 未保存
- 收盘态：完整 / 不完整
- 当前结论：盘中暂判 / 收盘确认
```


## 4. 高标回放模板

### 4.1 判定目标

高标回放重点不是问“它高不高”，而是问：

- 它是不是只有高度，没有领导权

### 4.2 模板

```text
【高标样本】
交易日：
股票：
代码：
题材：
战场：

一、为什么它像龙
- 高度：
- 连板：
- 市场关注度：

二、为什么它不是龙
- 因果门是否失败：
- 分歧门是否失败：
- 是否无跟风：
- 是否一字孤勇：
- 收盘是否被反超：

三、结论
- authority：HEIGHT_ONLY / 其他
- 是否进入高标榜：
- 为什么只能看不能当真龙：
```

### 4.3 高标回放时最要命的一句

高标模板里最好强制补一句：

```text
- 它有没有“高度先于带动”还是“带动先于高度”：
```

不写这句，回放很容易又滑回“板高最大就是龙头”。


## 5. 热度票回放模板

### 5.1 判定目标

热度票回放重点是：

- 它是不是注意力中心
- 但不具备领导权

### 5.2 模板

```text
【热度样本】
交易日：
股票：
代码：
题材：
战场：

一、热度信号
- 个股热度：
- 人气：
- 人气变化：
- 所属题材热度：

二、为什么不是龙
- 是否启动滞后：
- 是否只是被主线抬热：
- 是否没有带出 follower：
- 是否尾盘才冲热：

三、结论
- authority：HEAT_ONLY / 其他
- 是否进入热度榜：
- 为什么不能追：
```

### 5.3 热度样本的补充问法

建议再补两个问题：

- 它的热度是主动打出来的，还是被主线映射出来的
- 如果把热度拿掉，它还剩下多少领导权证据


## 6. 伪龙回放模板

### 6.1 判定目标

伪龙样本必须回答三件事：

1. 为什么盘中像龙
2. 为什么最后不是真龙
3. 为什么追它容易死

### 6.2 模板

```text
【伪龙样本】
交易日：
股票：
代码：
题材：
战场：

一、为什么像龙
- 早盘表现：
- 热度表现：
- 身位表现：
- 市场错觉：

二、为什么不是真龙
- 哪一道门没过：
- 被谁反超：
- 失位发生在什么时候：
- fatal negative 是什么：

三、为什么追会死
- 次日承接问题：
- 一致性问题：
- 尾盘失位问题：
- 热度大于领导权问题：

四、结论
- authority：PSEUDO_LEADER
- 是否进入墓地：
- 最终教训：
```

### 6.3 伪龙模板要逼自己写“失位时点”

最好不要只写“后来不行了”。

建议强制写成下面这种格式：

```text
- 失位时点：早段 / 中段 / 尾段 / 收盘
- 失位方式：被同战场反超 / 无跟风 / 尾盘抢热 / 收盘门失败
```


## 7. 一天多战场轮动时怎么记

如果一天内有多个候选，记录时不要混成一锅。

推荐按这个顺序写：

1. 先列战场
2. 再列每个战场主将
3. 最后再看有没有市场总龙头

一个标准日记结构：

```text
战场 A：
- 候选 1
- 候选 2
- 最终主将

战场 B：
- 候选 1
- 候选 2
- 最终主将

市场总龙头：
- 有 / 无
- 为什么
```

### 7.1 盘中多战场时的正确写法

交易时段尤其不要直接写“今天龙头是 X”。

更好的写法是：

```text
主战场候选：
- A 题材：X、Y
- B 题材：M、N

盘中领先者：
- A 题材当前像龙的是 X
- B 题材当前像龙的是 M

收盘再确认：
- 谁真过四道门
- 谁只是高标
- 谁只是热度
```


## 8. 回放时最容易犯的错

### 8.1 用收盘后结果倒推盘中逻辑

错误。

回放必须尊重时间顺序：

- 它先动没
- 它带人没
- 它中途被检验没
- 它收盘还站着没

### 8.2 只盯高度

高标是高标，龙头是龙头。

### 8.3 只盯热度

热度是结果，领导权才是核心。

### 8.4 把所有失败样本都扔墓地

墓地不是垃圾桶。

只有“像龙但最后不是龙”的样本才配进墓地。

### 8.5 在交易时段提前写死 `authority`

这也是常见错误。

如果当天还没有：

- 收盘态
- 日级快照

那更稳妥的写法应该是：

- `authority：待收盘确认`

而不是提前写成：

- `authority：TRUE_LEADER`
- `authority：HEIGHT_ONLY`
- `authority：HEAT_ONLY`


## 9. 如何和代码结果对照

回放完以后，建议用下面几个字段和系统结果做对照：

- `battlefield.themeName`
- `battlefield.dominance`
- `leader.authority`
- `leader.primaryRole`
- `leader.tradeability`
- `leader.chaseRisk`
- `leader.timeline`
- `pseudoLeaderGraveyard`

再补三条：

- `reviewCompleteness`
- `summaryLines`
- 面板里的样本来源标签：`真龙榜 / 高标榜 / 热度榜`

如果你发现：

- 列表里一堆 `SPACE_CORE`

不要立刻推断后台只算出了空间龙头。

先确认：

- 这些样本是不是主要来自 `高标榜`
- `分角色` 里确认真龙是不是其实并没有那么多
