## 目标

行情列表“主力净额”和题材分析器“主力资金”只消费一份通达信逐笔计算结果，消除前端对资金接口的周期性 HTTP 轮询。单笔成交额大于或等于 30 万元计入主力资金。

## 范围

- 数据源切换为 `python-bridge` 的 `tdx_transaction`，不再使用 THS 或东财资金行。
- `python-bridge` 只负责读取逐笔成交、计算单股票累计资金帧，并通过现有 WebSocket 输出。
- QuantBoard 是桥接流的唯一服务端订阅者：保存最近成功行、聚合题材、向 Dragon Board 二次推送。
- Dragon Board 首次连接接收资金快照，之后仅接收按股票代码变化的增量；行情列表和题材面板读取同一前端资金索引。
- `tools/THSBigOrder` 是独立单票监控工具，不在本次范围内修改。

## 数据口径

对每笔逐笔成交，成交额为 `price * volume * 100` 元。仅金额大于或等于 300,000 元的主动买入和主动卖出参与主力计算：

```text
主力净额 = sum(主力主动买入) - sum(主力主动卖出)
```

无法判定方向的成交不进入净额；缺失或尚未采到资金仍为 `null`，不能写为 `0`。输出来源标记为 `tdx_transaction`，并附带源时间、更新时间和单调版本号。

## 订阅和缓存

QuantBoard 在生命周期内保持一个到 `ws://127.0.0.1:8765/ws/quotes` 的重连订阅。它将桥接的 `moneyFlow` 变化写入 Redis，保留最近成功值；桥接短暂断开时继续服务缓存并重连，不把缓存清空。每条记录包含 `tradingDate`、源时间、更新时间、版本和 `isFinal`。收盘时，最后一条当日累计值被冻结为该交易日快照。

浏览器连接 QuantBoard 的资金 WebSocket。首帧为当前订阅股票的快照；后续帧只包含变化股票。浏览器断线重连时以最后版本请求增量，服务端无法补齐时再发送快照。REST 资金端点仅保留首屏/恢复兼容，不参与定时刷新。

非交易时间始终读取最近交易日的冻结快照，例如周六读取周五收盘数据，不按自然日置空。仅当 Redis 从未保存过某股票的最近交易日冻结记录时，才显示 `--`。bridge 以 `mootdx` 的通达信标准交易日历确定最近交易日；日历不可用时停止回填和冻结，保留 Redis last-good，不使用周末或自定义节假日猜测。盘后冷启动通过历史逐笔分页回填当天数据，只有回溯到开盘边界或收到盘中完整累计帧后才标记全天最终值。

## 采集范围与边界

通达信逐笔读取不是交易所推送。桥接当前按周期读取成交，因此只订阅当前行情可见股票、已展开题材成分股和用户关注股票的并集；不对全部题材映射股票进行高频扫描。每次订阅集合变化后，桥接按当前批量能力轮转采集。

题材映射的约 4,000 余只股票仍是归属全集，行情列表的约 200 只股票仍是展示子集；两者数量不作为覆盖率条件。对同一股票代码，两处必须读取同一版本的资金行。

## 验收

1. 资金展示链路没有 THS 或 `/api/quotes/eastmoney` 请求，也没有“资金数据降级”文案。
2. 单笔小于 30 万的成交不改变主力净额；等于 30 万的买卖成交按方向计入。
3. 前端稳定运行期间不再轮询资金 REST 接口；收到增量帧后，行情与题材值同步更新。
4. 桥接或 Redis 暂时不可用时，已有资金继续显示最近成功值，未采到的值显示 `--`。
5. `tools/THSBigOrder` 的代码、接口和行为保持不变。
