# 竞价弱转强检测器

## 概述

竞价弱转强检测器在集合竞价至开盘初期检测"由弱转强"的形态：昨日弱势（炸板/烂板/深水下跌）的票，在集合竞价阶段出现资金抢筹，开盘后承接有力、持续走强。

检测链有 4 个时间窗口，按优先级链（1→2→3→4）串行升级，同优先级不再拦截（`<` 比较），由检测器内部状态去重。

## 时间窗口总览

```
09:20 ─── 09:24:50 ─── 09:25:10 ─── 09:30 ─── 09:35 ─── 10:00
  │          │            │           │         │         │
  │     checkpoint 1      │    check2  check3   check4
  │    (竞价量价确认)      │   (开盘承接) (趋势确认) (终态记录)
```

四个锚点各有 ±30 秒（`CheckpointWindowThresholdSeconds`，可配）检查窗口。

## 检测链路

### Checkpoint 1 — 竞价量价确认（09:24:50–09:25:10）

**目的**：确认集合竞价阶段存在资金抢筹行为。

在窗口内，用两个基线段做对比：

- **初始基线**：09:20:00–09:20:30，代表竞价早期价格和成交额
- **临门基线**：09:24:00 起第一条记录，代表竞价尾段主力动向
- **最终基线**：09:24:50–09:25:10，代表竞价结束时的最终价格和成交额

量价双确认采用 **OR 逻辑**（二选一即通过）：

#### 子形态 1A：全段推（全程抢筹）

| 条件 | 默认阈值 | 参数名 |
|------|---------|--------|
| 全段价格推升 ≥ 阈值 | 0.8 个百分点 | `AuctionPriceLiftMinPctPoint` |
| 全段成交额翻倍比 ≥ 阈值 | 0.35 | `AuctionAmountLiftMinRatio` |

特征：09:20 低开后，资金从始至终持续买入，量价同步爬升。常见于昨日炸板/烂板票，集合竞价一开始就有资金进场承接。

#### 子形态 1B：临门突袭（尾段抢筹）

| 条件 | 默认阈值 | 参数名 |
|------|---------|--------|
| 临门价格推升 ≥ 阈值 | 0.3 个百分点 | `AuctionLatePriceLiftMinPctPoint` |
| 临门成交额翻倍比 ≥ 阈值 | 0.2 | `AuctionLateAmountLiftMinRatio` |

特征：09:20–09:24 平淡甚至走弱，09:24 后突然放量拉升。主力刻意压盘到最后一分钟才出手。

**不通过 → 链条终止**，该票当日不再检测。

---

### Checkpoint 2 — 开盘承接（09:30 ± 窗口）

**目的**：确认开盘后价格和量能对竞价形成有效承接。

4 个条件**全部满足**才触发 `gapAlert`（升级到趋势观察）：

| 条件 | 默认阈值 | 参数名 |
|------|---------|--------|
| 现价涨幅 − 竞价涨幅 ≥ 改善阈值 | 1.2 个百分点 | `OpeningSupportImproveMinPctPoint` |
| 现价 ≥ 竞价价 | — | — |
| 开盘价 ≥ 竞价价 | — | — |
| 成交额 ≥ 竞价成交额 × 量比 | 1.0 | `OpeningSupportAmountMinRatio` |

#### 形态 2A：跳空高开接力（gapAlert）

竞价量价确认 → 09:30 开盘承接改善 ≥ 1.2%，形成"竞价推→开盘跳"的接力。进入趋势观察阶段。

#### 形态 2B：竞价通过但开盘无力（noGap）

竞价量价确认通过，但 09:30 改善幅度不足阈值，或开盘价/现价跌穿竞价价。记录 `noGap` 但不播报。**注意：noGap 不会终止检测链**，09:35 仍会评估趋势，可能进一步触发 `trendWeak`。

---

### Checkpoint 3 — 趋势确认（09:35 ± 窗口）

**目的**：确认开盘后趋势延续而非诱多冲高回落。

需要 `gapAlert` 已触发才进入。4 个条件**全部满足**才升级为 `trendConfirm`：

| 条件 | 含义 |
|------|------|
| 现价 ≥ 开盘价 | 没破开盘价 |
| 现价涨幅 ≥ 竞价涨幅 | 相对竞价没有回落 |
| 现价涨幅 − 竞价涨幅 ≥ 改善阈值 | 改善幅度维持（复用 checkpoint 2 阈值） |
| 成交额 ≥ 竞价成交额 | 量能持续 |

#### 形态 3A：高开高走确认（trendConfirm）

gapAlert → 09:35 价格继续高于开盘价，涨幅扩大，量能跟上 → 最终确认弱转强成功。播报优先级最高。

#### 形态 3B：高开低走转弱（trendWeak）

gapAlert 触发后，09:35 价格回落破开盘价或涨幅缩水。记录 `trendWeak`，视为转强失败。

---

### Checkpoint 4 — 终态记录（10:00 ± 窗口）

- **已转强的票**（gapAlert 或 trendConfirm 已触发）：静默跳过
- **从未转强的票**：记录 `optionalFinalStatus`（不播报），标记"10:00 窗口结束未转强"

---

## 完整路径汇总

```
路径一（全段推→接力→高走）：1A → gapAlert → trendConfirm  ← 最强形态
路径二（临门突袭→接力→高走）：1B → gapAlert → trendConfirm
路径三（全段推→接力→回落）：1A → gapAlert → trendWeak
路径四（临门突袭→接力→回落）：1B → gapAlert → trendWeak
路径五（竞价通过→开盘失败）：1A/1B → noGap → [trendWeak]
路径六（竞价未通过）：链条不启动
路径七（开盘失败→趋势续弱）：1A/1B → noGap → trendWeak
```

## 参数清单

| 参数 | 默认值 | 作用阶段 | UI 标签 |
|------|--------|----------|---------|
| `AuctionPriceLiftMinPctPoint` | 0.8 | 全段推价格 | 全段推价 % |
| `AuctionAmountLiftMinRatio` | 0.35 | 全段推量比 | 全段推量比 |
| `AuctionLatePriceLiftMinPctPoint` | 0.3 | 临门突袭价格 | 临门推价 % |
| `AuctionLateAmountLiftMinRatio` | 0.2 | 临门突袭量比 | 临门推量比 |
| `OpeningSupportImproveMinPctPoint` | 1.2 | gap & trend 改善阈值 | 承接改善 % |
| `OpeningSupportAmountMinRatio` | 1.0 | gap 量能承接比 | 开盘承接量比 |
| `CheckpointWindowThresholdSeconds` | 30 | 所有检查窗口宽度 | 窗口阈值(秒) |

所有参数均可在设置面板的「异动参数」区域调整。

## 去重与升级规则

- Priority 链：`auctionConditionPassed/Failed(1)` → `gapAlert/noGap(2)` → `trendConfirm/trendWeak(3)` → `optionalFinalStatus(4)`
- 同优先级比较使用 `<`（允许升级），检测器内部状态去重
- `_strongToday` 持久集合：记录当日已确认转强的票，跨 Clear()/重连存活
- 10:00 终态检查：已转强的票静默跳过，未转强的记录失败状态

## 数据采集

- 09:20:00–09:25:10 窗口内的行情纳入样本，保留最近 16 条
- 16 条上限基于 5 分 10 秒窗口内 ~3 秒/条（通达信 L1 推送频率约 3–5 秒）
- 样本过多会导致基线计算偏离竞价实际趋势，过少则覆盖率不足
