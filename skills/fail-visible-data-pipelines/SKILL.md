# 数据链路主动暴露

## Overview

观察型数据链路必须 fail visible：保留已有数据、计算可计算部分，并把质量问题结构化暴露。数据质量只能影响可信度和派生结论，不能阻止保存、读取或查看。

## 强制边界

- 采集、清洗、写库、同步、迁移和缓存不得因字段缺失、覆盖率不足、非标值、时间乱序、部分来源失败或低样本而丢弃已有记录。
- 读取、查询、回放和 UI 不得因质量问题返回空集合、隐藏记录、裁成单帧或拒绝用户查看。
- 缺失值保持缺失。禁止用 `0`、空对象、空数组、其他评分或上一帧数据静默伪装当前缺失。
- 因子相互独立时按字段或轨道降级；一个字段缺失不得抹掉其他可计算结果。
- 派生交易结论可以标记为不可用或低可信，但必须同时返回原始数据、可计算部分、缺失位置、来源状态和结构化原因。
- 只有所有来源都没有任何原始记录时，才可报告本轮无数据。精确重复写入的幂等跳过、权限控制、不可逆删除或覆盖和真实交易执行不属于数据质量门禁。

## 编码前检查

1. 沿调用链找出所有 `return null`、`return []`、`fallback = 0`、`filter invalid`、`minimum coverage`、`gate/block/reject` 分支。
2. 对每处分支判断：它保护的是不可逆操作，还是仅仅因为数据不完整。后者必须改为保留并打标。
3. 明确定义部分结果合同，至少区分真实零值、缺失值、不可计算值和质量问题。
4. 让质量问题通过公开 API、日志或界面主动可见，不得只留在内部控制台。

## 必须验证

- 部分来源或部分字段异常时，已有原始记录仍然落库。
- 相同异常下，读取和回放仍返回已有记录。
- UI 展示可计算值和明确的缺失状态，不出现伪造的 `0` 或整体空白。
- 独立分析轨道不被无关字段连带清空。
- 结构化问题包含位置、原因和受影响范围。
- 全源无数据时明确报告无数据，不伪造成功。

发现“为了安全先不展示或不写入”“给默认零值保持类型稳定”“质量不足就返回空结果”等想法时，立即停止。这些都是观察型数据系统中的数据损失或数据伪造，不是安全措施。
