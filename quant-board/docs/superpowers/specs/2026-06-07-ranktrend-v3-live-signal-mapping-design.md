# RankTrend V3 实盘信号映射到行情列表——设计规格

日期：2026-06-07 | 状态：待用户审阅

## 动机

`bt_24bce043660b48ec` 这条 2026 年 5 月窗口回测对应的主线口径，已经明确为：

- `ranktrend_early_big_move_v3`
- `snapshot_type=half_hour`
- `execution_mode=current_bar`
- `maxHoldingBars=30`

当前 Dragon Board 行情总览中的【信号】列仍以旧的通用 `buy/sell/hold` 或 jump 标记为主，不适合第二天直接拿来做 V3 实盘盯盘。用户希望把这套回测中满意的 V3 买卖规则，整理成文档，并直接映射到行情列表【信号】字段上，作为明日盘中验证入口。

## 目标

1. 在 QuantBoard 文档区沉淀一份 V3 实盘动作口径说明。
2. 将 Dragon Board 行情总览【信号】列改成面向盯盘的 `V3 实盘动作标签`。
3. 第一版优先支持买点和转弱卖点，不强行伪造持仓依赖信号。

## 非目标

- 不接入 QuantBoard 回测报告作为行情表实时数据源。
- 不新增后端 API。
- 不重构整个 DataTable。
- 不在第一版里实现完整持仓账本。
- 不在第一版里为了 `连续 3 个 bar 离榜` 新建复杂跨日状态系统。

---

## 1. 展示口径

行情总览【信号】列改为显示以下 7 类 `V3 实盘动作标签`：

1. `止损卖出`
2. `转弱卖出`
3. `离榜卖出`
4. `A主升买点`
5. `B点火买点`
6. `持有观察`
7. `无信号`

### 1.1 优先级

同一只股票同一时刻如果同时命中多个条件，按以下优先级只显示一个标签：

1. `止损卖出`
2. `转弱卖出`
3. `离榜卖出`
4. `A主升买点`
5. `B点火买点`
6. `持有观察`
7. `无信号`

### 1.2 颜色方向

- 买入类：强调色，突出动作机会
- 卖出类：风险色，突出退出动作
- 观察类：中性色

具体样式沿用现有 DataTable badge 体系，不额外引入新 UI 框架。

### 1.3 Tooltip

tooltip 至少展示：

- 命中的规则名
- 关键阈值
- 当前触发值
- 是否属于“完整支持”或“降级判断”

## 2. 信号映射规则

第一版优先基于前端已存在的 `stock.rankTrend`、`candidateTier`、`jump`、技术信号、涨跌幅和在榜状态映射，不额外依赖 QuantBoard 回测明细。

### 2.1 `A主升买点`

触发条件：

- `candidateTier == A_MAIN`
- `jump.direction == 'buy'`
- `jump.confidence >= 90`
- `short > 0`
- `mid > 0`
- `long > 0`
- `acceleration >= 10` 或 `accDelta >= 8`
- `change < 6`
- 非涨停不可买

说明：

- 不要求 `finalSignal == buy`
- 本质上对应 `ranktrend_early_big_move_v3` 的 A_MAIN 入场规则

### 2.2 `B点火买点`

先满足共同门槛：

- `jump.direction == 'buy'`
- `jump.confidence >= 90`
- `short > 0`
- `mid > 0`
- `long > 0`
- `acceleration >= 10` 或 `accDelta >= 8`
- `change < 6`
- 非涨停不可买

再满足：

- `candidateTier == B_IGNITION`
- `mid >= 20`
- `zeroCross == 'buy'`

说明：

- 本质上对应 `ranktrend_early_big_move_v3` 的 B_IGNITION 额外确认条件

### 2.3 `转弱卖出`

第一版完整支持以下两类触发：

- `rawChange < -50` 且 `MACD cross == death`
- `candidateTier == D_EXIT_RISK`

说明：

- 这是 V3 里最适合直接映射到实时表格的卖出信号
- 如果两类同时命中，tooltip 同时展示

### 2.4 `止损卖出`

理想触发：

- 已持仓前提下，浮亏 `<= -5%`

第一版口径：

- 仅当现有前端已存在可靠持仓成本/浮盈亏上下文时才显示
- 如果缺少持仓上下文，不做猜测，不伪造为实时可用信号

### 2.5 `离榜卖出`

理想触发：

- 连续 3 个半小时 bar 不在热榜

第一版口径：

- 仅当现有前端已存在稳定的“连续离榜计数”来源时才显示
- 如果只有单帧“当前不在榜”信息，则不伪造成 `离榜卖出`

### 2.6 `持有观察`

触发条件：

- 仍属于 `A_MAIN` / `B_IGNITION` 候选，但未达到明确买点或卖点
- 或处于 `C_CROWDED` / `N_NEUTRAL`
- 或卖出类信号因为缺少持仓/跨 bar 上下文无法完整确认

### 2.7 `无信号`

触发条件：

- 当前数据不足以进入上述任一类别

## 3. 第一版实现边界

### 3.1 完整支持

- `A主升买点`
- `B点火买点`
- `转弱卖出`
- `持有观察`
- `无信号`

### 3.2 条件支持

- `止损卖出`
- `离榜卖出`

如果实现阶段确认前端已有稳定上下文，可接入；否则保持降级处理，并在 tooltip 中明确说明“当前版本未接入持仓/连续 bar 状态”。

### 3.3 禁止事项

- 不把 QuantBoard 的回测交易记录直接灌入 Dragon Board 行情表
- 不把 DataTable 变成回测终端
- 不绕过现有前端 RankTrend 数据流，直接拼一套新的信号来源

## 4. 模块设计

### 4.1 新增纯函数模块

建议新增一个窄作用域纯函数模块，放在 `src/services/rankTrend/` 附近，例如：

- `src/services/rankTrend/liveV3SignalMapper.ts`

职责：

- 输入单只股票当前的前端行情/RankTrend 数据
- 输出统一的 `V3LiveSignalDecision`

建议输出结构：

```ts
type V3LiveSignalLabel =
  | 'A主升买点'
  | 'B点火买点'
  | '转弱卖出'
  | '止损卖出'
  | '离榜卖出'
  | '持有观察'
  | '无信号'

interface V3LiveSignalDecision {
  label: V3LiveSignalLabel
  tone: 'buy' | 'sell' | 'watch' | 'neutral'
  reasons: string[]
  degraded?: boolean
}
```

### 4.2 `DataTable.vue`

改动点：

- 继续复用现有 `jumpSignal` 列位置，不新增第二个“信号”列
- 将现有列的内容改为读取 `V3LiveSignalDecision`
- tooltip 改为展示 V3 规则解释，而不是旧 jump-only 解释

### 4.3 与现有 jump 逻辑的关系

- jump 检测结果继续作为 V3 买点条件的一部分
- 但列表展示不再只表现为 jump 标记
- 新展示口径以“V3 实盘动作”优先，jump 退居为输入条件

## 6.1 实盘盯盘刷新机制

【信号】字段不是只在手动刷新页面时变化。

- 交易时间内，行情自动刷新主链每 `30 秒` 运行一次。
- 每次这条自动刷新链路完成后，会顺带重算一次 RankTrend 实盘信号。
- 因此页面保持打开时，【信号】字段会随自动刷新更新，不依赖手动 `F5`。
- 非交易时间不会触发这轮自动信号重算。
- 原有 `14:45` 的专项 RankTrend 信号刷新仍然保留，作为日内固定补刷点。

换句话说，明日实盘盯盘的默认口径是：

- 页面常驻打开
- 交易时按 `30 秒` 级别自动更新信号
- 不要求人工频繁刷新页面

## 7. 风险与限制

1. `止损卖出` 本质依赖持仓成本，没有持仓上下文时不能假装准确。
2. `离榜卖出` 本质依赖连续 bar 状态，只有单帧在榜信息时不能假装准确。
3. 当前列表是“实盘盯盘辅助”，不是“自动交易执行器”；展示为动作标签，不代表系统已经完成成交跟踪。
4. 第一版目标是让明天可以盯盘，不是一次性把完整实盘交易系统做完。
