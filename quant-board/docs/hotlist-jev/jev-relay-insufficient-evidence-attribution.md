# relay「证据不足」（IE）归因诊断（v4 单代 108 篇，2026-10-17）

> 触发：用户 2026-10-17 追问三批 IE —— 相位 14 天、边际 7 天（**实为 8 天**，用户表漏 09-04）、
> 连板梯队 3 天（07-06/07-07/07-09，即「15:00 帧未采」的 3 天）。
> 样本：单代 v4 全量 108 篇（2026-05-06..10-16）。**零模型调用**取证（只读 Mongo）。
> 本文**只记录归因，不含修复方案**（预注册另立；用户 2026-10-17 明确「不急预注册，先记下来」）。

## 0. 结论先行

两批 IE **同一根因**：**THS 15:00 炸板池的个股 items 有 19 天不可用** ——
16 天帧存的是旧 schema（只有家数 `poolCounts.failed`、无个股 code），3 天 15:00 帧压根未采。

该池是【今日炸板面】唯一数据源，而炸板面同时是：
- `relay_phase` 的**核心锚**（判据明示「叙事中晋级率/断板表现/炸板面/梯队证据缺失时选 insufficient_evidence」）；
- `relay_momentum` **主锚的一半**（判据明示「三日晋级链/炸板面对比证据缺失，无法判断」）。

⇒ 相位 IE = 炸板面**当日**证据缺位；边际 IE = 炸板面**较昨日对比**缺位（今日或昨日任一缺即不可算）。

**模型不是机械执行判据**：同缺锚的 30 天里只有 14 天相位 IE、8 天边际 IE，其余 22 天仍给出实相位
（07-30 divergence、08-19/09-02/09-23 collapse…，conf 0.3~0.9）。即缺锚抬高判定阈值，
在**本来两可**的日子 IE 才险胜（05-12：IE 0.37 vs divergence 0.30；08-25：IE 0.45 vs holding 0.42）。

## 2. 边际 IE（8 天）：单一根因 = 炸板面「较昨日」对比不可算

8 天：`07-09 07-31 08-20 08-25 08-26 09-04 09-14 09-24`（**09-04 为用户表所漏**）。

| 日期 | 缺位方向 | 叙事原文（炸板面行尾） |
|---|---|---|
| 07-09 | 今日 15:00 帧未采 | `今日炸板面：不可算（THS 炸板池缺失/降级，fail-visible）` |
| 07-31 / 08-26 | 今日旧 schema | 同上 |
| 08-25 | **昨日**（08-24 旧 schema） | `较昨日：不可算（昨日 THS 炸板池缺失/降级）` |
| 09-04 | **昨日**（09-03 旧 schema） | 同上 |
| 09-24 | **昨日**（09-23 旧 schema） | 同上 |
| 08-20 | **昨日**（08-19 旧 schema） | 同上 |
| 09-14 | **昨日**（09-11 旧 schema） | 同上 |

覆盖检验（全库 108 天）：炸板面对比证据缺位日（今日整段缺 **19** 天 ∪ 较昨日不可算 **11** 天）= **30** 天；
**边际 IE 8 天全部落在该 30 天之内（越界 0）**，其余 22 天仍给出实相位。⇒ 缺位是**必要非充分**条件。

`relay_phase` IE 14 天与 `relay_momentum` IE 8 天交集仅 3 天（07-09 / 07-31 / 08-26），
即两问的缺位触发点不同（当日 vs 相邻两日对比），印证同一根因经不同入口显形。

## 3. 原料层证据

### 3.1 THS 15:00 帧两种 schema（108 个 relay 判定日内）

| 形态 | 天 | 字段 | 可取内容 |
|---|---|---|---|
| 新 | 89 | `thsPools.pools.<key>.items[]`（含 code/open_num） | 炸板面全指标 |
| 旧 | 16 | `thsPools.poolCounts`（`failed/rushing/drawdown`）+ `maxDrawdown/avgDrawdown` | 仅家数与回撤统计，**无个股** |
| 无帧 | 3 | 该日无 15:00 帧（07-06/07/09；其帧止于 14:00/13:30/09:30） | 无 |

实样对照（同一字段名，两种形态）：
- 旧（08-24）`{"source":"ths-limitup-pools","poolCounts":{"one":36,"two":5,"three":3,"four":1,"high":0,"failed":17,"rushing":14,"drawdown":9},"failedCount":17,"rushingCount":14,"drawdownCount":9,"maxDrawdown":-15.59,"avgDrawdown":-11.41}`
- 新（08-25）`{"ok":true,"source":"limitup-ths-pools","pools":{"one":{"ok":true,"key":"one","cate":"limit_up_one","total":56,"items":[…]}}}` → `_ths_failed_items` 取到 22 只（有 code）

### 3.2 读口当前行为（`zhaban_face_line`）

```python
items, found = _ths_failed_items(db, date, dataset_id)
if not found:
    return "今日炸板面：不可算（THS 炸板池缺失/降级，fail-visible）"
```
旧 schema 日 `items` 取不到 → 整段降为「不可算」，**连带丢弃同帧已有的家数/回撤/冲刺家数**
（§AGENTS 4.0「只要有可用数据，就必须展示可计算部分与缺失位置」不满足）。

### 3.3 归因顺序（AGENTS §1.2.6）

| 层 | 判定 | 依据 |
|---|---|---|
| ① 原料/语料供给 | **主因** | 16 天旧 schema + 3 天帧未采 + 2 天池史起点 |
| ② 题目设计 | **次因** | 判据把炸板面列核心锚并明示缺锚→IE；但模型未硬执行（30 缺位日仅 14/8 落 IE），故只是抬高阈值 |

## 6. 连板梯队（ladder_health）IE（3 天）：**读口径硬门禁**，非缺原料

3 天 = `07-06 07-07 07-09`（恰为「15:00 帧未采」的 3 天）。叙事表现为
`梯队结构量化：梯队数据缺失（fail-visible）` + `盘面事实：<date> 盘面指标缺失（fail-visible）`。

### 6.1 直接原因（代码层）

`jev_label_jiuyan.market_metrics()` 只读 **15:00 帧**，并在**已算出梯队的下一步**做整段早退：

```python
jiuyan_ladder = _jiuyan_ladder(db, date, dataset_id)     # ← 主源，不依赖帧
...
if not zb.get("ztCount"):                                # ← 帧缺失 → 整段 None
    return None
```

`ztCount`（涨停家数）与梯队无关，但它的缺失把**盘面事实 + 梯队**整段置 None →
`ladder_structure_line` 得到空 ladder → 写「梯队数据缺失」→ `ladder_health=IE`。

### 6.2 梯队数据其实在库（实测）

| 日期 | 韭研 final | `_jiuyan_ladder` 桶 | caliber | `market_metrics` | 15:00 帧 |
|---|---|---|---|---|---|
| 07-06 | 96 只 | one 76 / two 8 / three 3 / four 4 / high 5 | touch_range | **None（早退）** | 无 |
| 07-07 | 48 只 | one 41 / two 4 / high 3 | touch_range | **None（早退）** | 无 |
| 07-09 | 88 只 | one 76 / two 7 / three 3 / high 2 | touch_range | **None（早退）** | 无 |

⇒ 梯队**可算且已在内存中被算出**，被 `ztCount` 守卫丢弃。触板口径（THS 炸板池缺失日的既有回退）
本就会在叙事里披露（`（THS炸板池缺失，梯队按触板口径）`），所以展示它不构成伪数据。

### 6.3 归因（AGENTS §1.2.6）

| 层 | 判定 | 依据 |
|---|---|---|
| ① 原料 | 触发源 | 15:00 帧未采（与 §1 组 B 同源，不可回补） |
| ② 代码读口径 | **放大原因（可修）** | 单字段守卫丢弃整段可用数据；与 §AGENTS 4.0「有可用数据就必须展示可计算部分」冲突 |
| ③ 解析 | 无问题 | answers 完整；`status=ok` |
| ④ 方案重设计 | 不需要 | — |

### 6.4 候选动作（未立预注册）

**字段级降级**：`ztCount` 缺失时，涨停家数/炸板率/回撤/最高板写「不可算」，但**梯队（韭研源，不依赖帧）
照常输出**并带口径披露。影响面：仅 3 天叙事变更（07-06/07/07/07-09）→ 重判 ≈20K tokens；
可与 §5-1「旧 schema 同源降级」合并为一次 v4→v5。
⚠️ 不建议改读 14:00/13:30 帧的 `ztCount` 顶替 EOD 口径（盘中 ≠ 收盘，属口径混用）。
