# 隔日弱转强全史统计（2026-10-21）

> 用户问询：10-21 涨停 50 / 跌停 5 / 反包 12，较昨日是否典型弱转强？历史上一共出现过多少次？
> 本文为研究统计档案（口径预注册 + 结果 + 局限），非打分维变更；反包率仍为当日状态锚专用因子（R3 §11.4）。

## 1. 口径预注册（先定规则后数数）

**主判定用 relayIndex**（`hotlist_jev_relay_index`，情绪唯一打分维，111 个交易日 2026-05-06..10-21 全覆盖）：

- **弱（T-1）**：relayIndex ≤ 40（弱势区）
- **强（T）**：relayIndex ≥ 50（中强区）且 ΔrelayIndex ≥ +10
- **结构确认**（家数证据，`frame_market_facts` 15:00 收盘口径 + `market_daily_limit_down` 全市场跌停）：
  跌停家数下降 或 涨停家数回升，至少其一

三者同时满足记 1 次「隔日弱转强」。辅助维度：炸板率、大面家数（drawdown）、最高板、反包率
（`hotlist_rewrap_pool` final，2026-05-06 起回填 111 日）、炸板回封率。

## 3. 关键统计

- **弱转强日反包率均值 7.7% vs 全体 5.7%**（+2.0pct）——反包确是弱转强日的显著特征，与
  R3「当日状态锚」定位互证（反包率高的日子情绪修复概率大，但不构成跨日预测维）。
- **T+1 延续率仅 3/18（16.7%）**：弱转强次日 relayIndex 平均 Δ≈-23，多数「一日游」；
  三次延续为 06-29（+17.2）、09-18（+9.3）、10-20→10-21（+8.7）。
- 弱转强日跌幅修复特征普遍：T-1 跌停中位 13.5 家 → T 中位 4.5 家（基线现算口径，落地行
  引用同源；初稿手写 12.5→3 系人工估值，以本行现算为准，2026-10-22 修正）；涨停中位 47→92。
- 历史最极端弱转强前夜：07-13（跌停 177）、09-28（跌停 56）、09-15（跌停 32）。

## 4. 10-21 的定位（回应用户）

- **10-19→10-20 是第 18 次弱转强**（46/22 跌停/idx37.4 → 52/5/idx50.1）。
- **10-21 是该次弱转强的 T+1 延续日**（idx 58.8，Δ+8.7），是全史第 3 次成功延续——
  但注意 10-20 relayIndex 50.1 已离开弱势区，按本口径 10-21 本身不构成新的弱转强；
  用户的直觉（50 涨停/跌停 5/反包 12 修复特征）与结构证据一致，只是 T-1 已不强。
- 口径注记：若把 T-1 阈值放宽到 ≤50，10-20→10-21 也计入，总次数 19，但会把
  「强区间内继续走强」混入统计，故维持 ≤40 的预注册口径。

## 5. 局限（fail-visible）

- relayIndex 自 2026-05-06 起有值；更早（03-27 起仅跌停家数）无法判 relay 弱强，未计入。
- 反包快照 2026-05-06 起回填，覆盖全部 18 次；炸板回封率 14/18 天可算（THS 炸板池缺口）。
- 判定阈值（40/50/+10）为预注册经验值，未做敏感性扫描；如需门控研究另立文档。
- 本统计为描述性档案，不构成交易规则；弱转强 T+1 低延续率本身是重要反直觉发现。

### 6.3 节点定格预注册（2026-10-22，用户裁决：判定标准必须稳定）

§6.1 暴露的根因是「节点判定依赖可变模型评分，重跑即改写历史」——信号前后不一致，
用户没有可依赖的判定标准。裁决如下：

- **判定标准 = 收盘首次落库定档（settlement），一次定格，重跑不改写**（first-write-wins）。
  定档条目（hit/continuation/prevIdx/idx/confirm/reason/state/settledAt）内嵌 relay 文档
  `wzs` 字段；重跑只更新叙事/评分，已定档节点原样随档。
- **未定档日回退现算**（classify_series 定格优先、现算兜底，单一事实源仍是
  analysis/hotlist/weak_to_strong.py，零第二份阈值）；continuation 链由定格 hit 传导。
- **语料行分歧注记**：重跑评分 ≠ 定档 idx 时，语料行显式写
  「重跑重评 X，节点以收盘定档 Y 为准」（fail-visible，不静默）。
- **历史回填**：`backend.cli wzs-settle-backfill --start --end [--idx-override 日期=指数]`，
  幂等；2026-10-22 执行 2026-05-06~10-21 → 111 日全部定档，其中 2026-10-20 引用本文档
  §1 存档定档值 50.1（收盘首次判定，重跑重评 47.8/46.4 不改写）。dry-run 命中清单与
  §1 的 18 次逐日一致；回填后基线恢复 18/7.7%/5.7%/3-18。
- **新交易日**：由 run_relay_index_day 落库时自动定档（_apply_settlement），无需人工回填。
- 测试：定格幂等/定格优先/链传导/重跑随档/分歧注记 5 例；tests/hotlist 1017 passed。

### 6.4 定档代际绑定与题集升代流程（2026-10-22 预注册）

节点定格锚定「评分代际」：40/50/Δ10 阈值是在 v7.1 分数分布上预注册的。若未来
relay 题集升代（v7.1→v8，打分规则改变）需要全量复跑情绪分，旧代定格对新序列
不再有裁决力，处理流程如下（与 driver 判据升代先例同哲学：跨代不可比）：

1. **新判据先预注册**（档案登记 v8 题集与打分规则），升代复跑 = 预登记开火路径；
2. **全量复跑情绪分**（真实 jev 调用，预算确认）；
3. **重跑本文档研究**：用 v8 新序列重新检验弱转强口径——阈值可能整体偏移
   （v8 分布 ≠ v7.1 分布），40/50/Δ10 必须重新门控/校准，或口径退役；
4. **`wzs-settle-backfill --reset` 重新定档**：旧代定格先自动归档
   `data/backups/wzs_settlements_<ts>.json`，再按新口径逐日重定档（可带
   --idx-override 引用重放后收盘定档值）；
5. **档案登记两代对照**（v7.1 节点清单 vs v8 节点清单，漂移即研究事实）。

机制实现：定档条目带 `gen=questionSetVersion`（本节起生效；无 gen 的存量档视作
v7.1 初代）；`_settled_stamps` 只采纳 gen=当前代 的定格，代际不匹配自动回退现算
（fail-visible：升代后未重定档期间节点显示现算值，不静默沿用旧档）；--reset 仅供
升代重放后使用，正常运行路径永远 first-write-wins。测试 3 例（gen 记录/旧代失效/
reset 重定档），tests/hotlist 1020 passed。
