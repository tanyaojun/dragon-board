## 一、为什么是「聚合锚」不是「板块指数」

判据需要的是「板块今天整体涨没涨、多少成员翻红」，不是千点指数。链式指数在成员
漂移下数学上不良定义（并集成員逐日变，基期连续性无意义）。V2 只做**逐日横截面
统计**，连续性问题自动消失。前端命名一律「活跃股聚合」，不得写「板块指数」。

## 二、成分口径（冻结）

- **滚动成员并集**：板块 B 在最近 N 个交易日（含今日）的韭研 final 池**涨停股**
  并集，**N=10 单算**（字段 `aggN10`；双算取消见头部口径修订）。
- 板块名逐日**精确匹配**（与 v1 同哲学）：改名板块窗口内旧名不算数，windowDays
  如实缩短并披露。
- 窗口不足 N 日（历史头部）→ 用可得日数计算，windowDays 披露实际值。
- 成分 = 活跃股 ≠ 全概念股：板块内不活跃的背景股看不到（PDF 口径本就只关注
  强势股群体，如实登记为已知局限）。
- 行覆盖 = aggN10 并集（⊇ v1 三日窗口）：**今日无涨停但 N 窗内曾有
  涨停的板块也有聚合读数**——家数=0 而聚合已翻红正是弱转强前兆的观察位。

## 三、逐日统计口径（冻结）

对成员集中「当日有棒且有昨收」的股票（quotedN）：

| 字段 | 定义 |
|---|---|
| pctMean | 等权平均涨幅 %（(close/prevClose−1)×100） |
| pctMedian | 中位涨幅 % |
| redRatio | 翻红率：close>prevClose 成员 ÷ quotedN（=0 算不红） |
| memberN | 成员总数（N 窗并集去重） |
| quotedN | 当日有棒且有昨收的成员数 |
| missingN | 缺棒/无昨收成员数（停牌、新上市），**剔除统计并披露，不伪装** |

- 日线棒来源：`_daily_bars`（本地 vipdoc 优先 + 线上补尾，生产既用链，逐股缓存）。
- 成交额合计（PDF 巨额投入锚）**不进 V2**：`_daily_bars` 无 amount 字段，
  留 V2b 分钟回放时一并研究量能。
- 版本戳：`AGG_VERSION = "2026-10-24a"`（独立于 SECTOR_NODE_VERSION，判据
  版本保持 v1 不动）。

## 六、韭研产业库发现登记（2026-10-24 抓包实测）

- 端点家族：`/api/v1/ai/industry/{list|cascade|stock-tree|stock-list|…}`（从页面
  JS bundle 抽取 + token 实调验证；今日累计消耗韭研 API 11 次调用）。
- 事实：一级节点 108 / 全树 768 节点；`stock-tree?code=一级code` 返回该产业
  **全成分股**（股票带 `stock_code`(sz/sh 前缀)/`stock_name`/`shares_range`
  关联强度/`content` 关联理由/`exaggerated_count` 夸大标记）；taxonomy 为驱动型
  三级树（国产机器人→宇树机器人→股权相关/合作商）。
- **不进 V2 主链的理由**：①活库无历史（国产机器人 create_time=2026-09-29，
  content 每日 15:0x 更新）——130 日回填不可能；②与 action 页板块名仍是两套
  名录（机器人 → 国产机器人+特斯拉机器人+机器人零部件+机器人应用场景拆分），
  映射仍需模糊匹配；③成分含 0.01% 级股权关联，噪声大。
- **定位**：立即归档（快照已落 `data/backups/jiuyan-industry-snapshot-20261024/`：
  cascade.json 全树 + stock-tree-0079 样本）+ 三期升格路径（见 §七）。
