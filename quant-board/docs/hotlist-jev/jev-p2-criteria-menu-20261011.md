## P2-1 crowd_clearing「明显回落」可数化

- **病灶**：v2.5 六层判据里 crowd_clearing 的「触及（≥p80）」允许贴线单轴触发、「明显回落」
  无可数定义（glm53-crowding-a1 §审定：5 幻觉全弃后保留的最小 diff 议题）。
- **提案骨架**（方案 B 观测量预登记）：判据文本不动，先登记三个候选回落量——
  ①当日 ztCount 较昨日降幅分位；②炸板率较昨日升幅分位；③高位梯队（二板+）家数较昨日降幅。
  待 10 月真实触发案例（v2.5 上线后 crowd_clearing 触发日）出现 ≥3 例，用案例回算三个量
  的实际读数，再冻结可数定义入 v2.6 判据包。
- **成本**：零 token（案例回算是只读统计）；判据文本改动入 v2.6 需另行预登记+重跑裁决。
- **验证门**：≥3 例真实触发案例回算 + 最小 diff 原则（只把「明显回落」绑定到一个观测量）。
- **前置**：10 月触发案例积累（当前 v2.5 上线约 1 周，crowd_clearing 属稀缺档）。

## P2-3 driver_type capital_flow 排除式判据改锚定式

- **病灶**：capital_flow 判据是排除式定义（「无明确新催化，主要由资金接力带动」）——
  排除式天然低置信（实测 topP50 0.66、骑墙 43.8%，全场最差之一）；与 concept_stretch
  边界互渗。
- **提案骨架**：给 capital_flow 换可数锚——③板以上梯队 + 板内封板时间偏晚 + 解析无新增
  事件行（三条件与 buy_side_logic 的 high_board_relay 口径对齐，题目间口径对齐纪律）。
- **成本**：判据改动=题目代际 v3.2；pilot 三天样本（≈21 万 tokens/日护栏的全量打标 run
  中的 3 天）+ 人工抽验 ≥5。
- **验证门**：预登记冻结判据 diff → 3 天 pilot → capital_flow 骑墙率显著下降且
  concept_stretch 误判不升 → 用户裁决落 v3.2。
- **前置**：先积累 capital_flow vs concept_stretch 的分歧样本（复核工作台自然积累），≥10 例
  再冻结（避免拍脑袋改门）。
