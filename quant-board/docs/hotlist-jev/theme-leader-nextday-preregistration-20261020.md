## 2. 语料盘点（实测证据）

### 2.1 韭研「异动」接口里没有板块级文本

`jiuyan_action` 的板块对象（`fields[]`）**只有三个键**：`name` / `count` / `stocks[]`
（全库 118 份文档取样，`field-level keys seen: ['count','name','stocks']`）。
个股条目才有 `expound`（异动解析全文，首行=涨停原因，正文=逐条核实段）。

### 2.2 板块内解析也不是"同一段板块文案复制"

若韭研把板块级催化写进每只成分股的解析，应能在同板块内看到**逐字重复行**。实测：

| 检验 | 样本 | 结果 |
| --- | --- | --- |
| 同板块内 ≥2 只股票出现**逐字相同**的解析行（≥20 字） | 97 个板块-日（10-09~10-19） | **0 行**（0%） |
| 同板块事件行的 3-gram Jaccard≥0.5 **聚类**（近似归并） | 26 个板块-日（10-16/19/20），334 条事件行 | **0 个跨股共享簇**（全部 size=1） |

结论：韭研的每只股票解析是**逐股手写**（公司自己的订单/中标/参股/产能事件），
板块级催化（GTC、Optimus、《物理 AI》）只是被**零星引用**在个别股票的解析里：

| 关键词 | 库内出现位置 | 文档数 |
| --- | --- | --- |
| GTC | 个股 `expound` | 8 |
| Optimus | 个股 `expound` | 24 |
| 物理AI | 个股 `expound` | 42（板块级字段 0） |

### 2.3 事件线索是有的，但没结构化

- 事件型行（命中公告/中标/订单/量产/发布/签约/涨价/政策/大会…）占解析正文 **58%**（中位 59.6%，174 个「连板且解析未变」样本）；
- 但它们是**公司绑定的**，不是板块绑定的；且没有「未来事件日历」这层（"10 月 20-22 日举行"这种**前瞻**信息只偶然出现）。

### 2.4 项目内其它语料（都不是新闻/事件流）

| 集合 | 内容 | 能否当题材催化语料 |
| --- | --- | --- |
| `themes.structure`（KPL 题材树） | 分支/子分支/成分股 + 每股静态逻辑 `reason`（如"通过参股央视融媒体基金间接投资松延动力"） | 只能当**静态素材**，无事件时点 |
| `theme_stock_mappings` | 题材×个股 tags/reason（多为因子型，如"应收总类/净资产:10.41"） | 否 |
| `theme_daily_factors` | 题材日频量化因子（热度/动量/拥挤度/分位） | **是"状态"不是"催化"**，可直接进叙事当结构化事实 |
| `jiuyan_action` | 板块名/家数/名单 + 个股解析 | 个股催化有，板块催化无 |

> 结论：`jiuyan_action` 与主题库集合里没有事件/新闻流；题材"催化"这一维原本只能靠个股解析侧面推断。
> **2026-10-20 补充**：韭研另有两条未被采集的端点（`/ai/industry/list`、`/timeline/*`），
> 实测就带着板块级催化原文与未来事件日历，见 §5.1（本节保留为"当时只有异动库"的记录）。

## 3. 结构基线：龙头隔日连板本来就有多可预测（零模型调用）

工具：`quant-board/scripts/theme_leader_sustain_baseline.py`（复用生产口径：`jiuyan_board_info`
触板−THS 炸板二分、`jiuyan_streak_map` 真连板；龙一=板块内真连板最高→封板最早；
结局=次一交易日是否仍在封板集合）。

窗口 2026-08-01~10-19（50 个可二分交易日，341 个「板块龙头-日」样本；THS 池缺失日如实跳过 14/9 天）：

**总体：次日继续封板 117/341 = 34.3%**

| 维度 | 分桶 | 样本 | 隔日连板率 |
| --- | --- | --- | --- |
| 真连板高度 | 1 板 | 156 | **19.2%** |
| | 2 板 | 90 | 44.4% |
| | 3 板 | 39 | 46.2% |
| | 4 板+ | 56 | **51.8%** |
| 当日板块涨停家数 | 1-2 | 101 | 22.8% |
| | 3-4 | 98 | 29.6% |
| | 5-7 | 79 | 43.0% |
| | ≥8 | 63 | **49.2%** |
| 龙头封板时间 | ≤10:00 | 210 | **42.4%** |
| | 10:00-13:00 | 67 | 17.9% |
| | >13:00 | 55 | 29.1% |
| 昨日同板块其它股封板数 | 0 只 | 202 | 29.2% |
| | 1-2 只 | 37 | 48.7% |
| | 3+ 只 | 10 | 90.0%（样本小） |

组合桶（n≥5）：

| 组合 | 样本 | 隔日连板率 |
| --- | --- | --- |
| 4板+ ｜板块≥8家 ｜早封 | 12 | **83.3%** |
| 3板 ｜5-7家 ｜早封 | 7 | 71.4% |
| 4板+ ｜1-2家 ｜早封 | 8 | 62.5% |
| 2板 ｜5-7家 ｜早封 | 18 | 55.6% |
| 2板 ｜≥8家 ｜早封 | 16 | **31.3%**（反直觉：大板块的 2 板更易被"抢位"分流） |

板块次日再出涨停家数分布：0 家 149（43.7%）、1 家 107、2 家 50、≥3 家 35。

**怎么读这张表**：
1. 结构特征（高度/家数/封板时间/昨日同伴）已经把概率拉开到 **19% → 83%**，这就是任何题材判定必须先
   超过的**基线**；
2. 同桶内仍有大幅方差（如 2 板+5-7 家+早封：55.6%，18 个样本里 8 个失败）——**这层残余方差才是
   题材催化/事件日历能贡献的空间**；
3. 反直觉桶（2 板+大板块 31%）提示「催化是否唯一/是否被稀释」是结构变量抓不到的东西——正是题材层
   要补的那一维。

## 4. 判据设计（题材层 → 隔日连板概率）

### 4.1 三层语料（按可得性排序，非按理想）

| 层 | 内容 | 来源 | 状态 |
| --- | --- | --- | --- |
| **L1 结构** | 真连板高度、封板时间、板块涨停家数、昨日同伴封板数、板内跟风数、龙头身位、板块热度/动量分位 | 现有生产口径 + `theme_daily_factors` | ✅ 已可算（§3 脚本） |
| **L2 派生板块催化状态** | 板块内当日**新增事件**的条数/类型分布/最新事件日期（从成分股 `expound` 事件行结构化聚合，**不伪造板块原文**），板块「催化和家数是否同向」 | 个股 `expound`（现有） | ✅ 可零成本实现 |
| **L3 前瞻事件日历** | 未来 1-3 日的既定事件（大会/发布会/政策窗口/解禁/财报）+ 当日盘中快讯 | **需新采集**（见 §5） | ❌ 缺 |

### 4.2 题集 v1（✅ 2026-10-20 定版落地：`analysis/hotlist/theme_leader_ammo.py`）

设计取舍：**不做「每板块 1 次日级 call + 龙头级 call」两级调用**，只做**龙头级 1 call**
（把板块级状态改为确定性派生——L3 证据块本身就是板块级事实，不需要再多花一次模型调用去"读"它）。
理由：①成本直降（每日 3 次调用→0 次额外 HTTP、模型调用数与板块数无关）；②板块级事实由
`theme_event_digest` 确定性拼装，可复现、可逐字审计，比模型转述更可靠。

**题集（v1，判据冻结）**：

| 题 | 档位 | 判据要点 |
| --- | --- | --- |
| `leader_nextday_continue` | `high_ge65` / `mid_45_65` / `low_25_45` / `verylow_lt25` / `insufficient` | 次一交易日继续封板概率档；**同桶历史基准率是必须先超的基准**，理由若仅为结构特征须与基准同档；题材证据权重高于结构；关键证据缺失必须判 insufficient |
| `catalyst_stage` | `new_today` / `ongoing` / `stale` / `none` / `insufficient` | 以 L3 证据块为准判催化阶段（正文更新日 + 未来 3 日既定事件） |

代际戳：`QUESTION_SET_VERSION_THEME_LEADER="v1"`、`AMMO_VERSION_THEME_LEADER="2026-10-20a"`、
`QUESTION_SET_HASH_THEME_LEADER="ff010c50200e"`（冻结在 `tests/hotlist/test_theme_leader_ammo.py`：
判据改一个字就会打破测试，必须显式换代）。

**叙事固定六行**（顺序固定，便于逐字复现）：

```
{date} 交易日 · {盘面事实行（复用驱动链 market_facts_line，全日一致）}
待判龙头：{name}（{code}）
板块「X」今日封板 N 家；龙头 …{streak} 连板，首封 {time}；板块内真连板≥k 的跟风 M 家；{昨日该板块…}
结构基线（…）：同桶[streak3|n5-7|early<=10:00] 历史次日连板率 71.4%（7 样本）；按连板高度… ；总体 34.3%（341 样本）
题材语料：韭研产业树 + 投资日历，采集日 …（当日刷新/非当日，可能滞后）；76 条事件 / 730 个产业节点
【题材证据 · 韭研产业树 + 投资日历】
板块级催化原文（…匹配方式 exact，热度 …，正文更新 …）：…
未来 3 日既定事件（韭研投资日历）：- 2026-10-21（T+1） 英伟达GTC大会（重要度5，录入 …，题材:…）：…
```

**写入**：`hotlist_jev_theme_leader_labels`，`_id={date}:{code}`，origin=`theme_leader_label_v1`；
每条落 `structure`（连板/封板时间/家数/跟风/昨日延续）、`baselineBucket`+`baselineMeta`（同桶率与窗口）、
`evidenceState`/`evidenceIndustry`/`evidenceEventTitles`、`narrative`（逐字）、`answers`（原样）、
`leaderNextdayContinue`+概率、`catalystStage`+概率、usage/model/latency、`status`。
`outcomeSealedNextDay` **留空**：标签时点结局未知，由评估脚本次日回填（防 look-ahead）。

**与驱动链分集合存放**：题集/判据代际不同，混读会掩盖代际漂移。

**幂等**：同日同 code `status=ok` 跳过；`--force` 唯一例外（口径代际回放）。

### 4.3 成本与替代效应（关键）

- 现链路：逐股四题 ≈ **237k tokens/日**（72 只）。
- 题材层：**只给当日各板块龙头**打标 = **1 call/龙头/日**。2026-10-19 实测 **13 只龙头**
  → 叙事合计 12,759 字，上界估算 24.5k tokens/日 → **实开火实耗 29,014 tokens（已核销）**。
- **护栏常数已按实测校准**（2026-10-19，13 次真实调用）：估算 24,460 → 实耗 29,014（**低估 19%**）。
  逐条反推均字符 981、实耗均 2,232 tokens/次 ⇒ 真实固定开销 ≈1,250 tokens/次（原用 900）。
  `QUESTION_OVERHEAD_TOKENS` 已由 900 改为 1250（低估会让"用户批准的上界"失效，属预算护栏缺陷，已修）。
  > **已被 §10.5 取代**（2026-10-20）：v2 起护栏改按 22 条真实账线性拟合的上界公式
  > `low/high = 0.80/1.05×chars + 1,300/1,700`，不再使用单一 `QUESTION_OVERHEAD_TOKENS` 常数
  >（该常数已随 v1 公式淘汰，全仓无此代码，单读本节请勿误当现状）。
- 隐含前提取证：每日龙头数 ≈ 板块数（10-19 为 13），随题材发散度变化（题材爆发日可能 20+）。
  预算护栏按 `estimate_tokens` 上界口径逐日核算，并在 `--dry-run` 打印。
- 若题材层立得住（超同桶基线），下一步才是「只给龙头打标、非龙头停产」——那才是真正的
  token 降档（237k → ~25k），比 A+B 的 ≈2% 大一个量级。

## 5. 语料补齐：已解决（韭研自己就有，不需要外部源）

核实方法：韭研前端 bundle（`/_nuxt/9d1828e.js`）可枚举全部 API 路径，再逐个用现有认证链实测
（**零 jev 调用**，只花 HTTP）。结论：

| 端点 | 返回 | 用途 | 状态 |
| --- | --- | --- | --- |
| `POST /jystock-app/api/v1/ai/industry/list` | **AI 产业树**：730 节点 / 102 个一级板块，含 `group_name`、**`content`=板块级催化原文**、`hot` 热度、`update_time`、`children`（子行业各自也有正文） | **板块级催化（L3）** | ✅ 已采集 |
| `POST /jystock-app/api/v1/timeline/news {limit}` | **未来 1-3 日投资日历**（大会/发布会/财报）+ 当日「早报」事件清单 | **前瞻事件（L3）** | ✅ 已采集 |
| `POST /jystock-app/api/v1/timeline/list {limit}` | 时间轴：过去 ≈2 周 + **未来 ≈2 周**，每条带 `grade`(重要度)、`create_time`(录入时间)、`theme_list`(题材标签) | 事件新近度/重要度排序 | ✅ 已采集 |
| `POST /action/detail` | — | 当日 errCode=9（见 §5.3 定性：**限流**，非日额度） | ⏸ 冷却后单发再评估 |

首次采集实测（2026-10-20）：**76 条去重事件**（54 未来 / 42 已发生）+ **730 个产业节点**
（全部有 `content`；一级板块正文中位 94 字、最长 510 字）。真实样例：

- 「物理AI」content：`2026年6月5日讯，在2026中国台北GTC大会上，英伟达正式官宣 NVIDIA Cosmos 3，成为全球首款完全开放的全模态物理AI模型。`
- 「特斯拉机器人」content：`2026年9月25日，有媒体报道，特斯拉已将 Optimus 人形机器人产量扩大到约 10 倍…`
- 投资日历 10-21：`英伟达GTC大会`（重要度 5、录入 10-20、题材 无人驾驶/具身智能/物理AI）
- 当日早报：`物理AI：10月19日至22日物理AI领域多场大会密集举办，英伟达GTC大会10月20日至22日在德国柏林举行…`（**正是用户举例句子的同源**）

**原 §5 的四个选项作废**：不接财联社、不接同花顺、不接巨潮——同一源同一口径，
避免多源混采把口径做成"看着像催化"。

### 5.3 韭研题材端点的调用纪律（2026-10-20 实测，写死在采集层）

**errCode=9 的正确定性 = 短时限流，不是日额度耗尽**（先按“配额”理解，实测证伪）：

| 观测 | 结果 |
| --- | --- |
| 连发 6 次 `timeline/list` | **6/6 errCode=9**（msg=「非常抱歉！服务繁忙，请稍后再试！」） |
| 同一时段异动端点 `/action/count-pc`、`/action/field` | **errCode=0**（两套服务各自限流，不是同一计数） |
| 静默 ~20 分钟后重发同一请求 | **成功**返回完整数据（76 条事件 / 730 节点） |
| 刚成功后又连发 4 次 | 全部 errCode=9，**连对照组的已知可行形状也变 9** → 是限流不是参数问题 |
| **换新账号**（`.env.local` 新 `JIUYAN_PHONE/PASSWORD`，会话+token 已换）后单发 | 异动端点 `/action/count-pc` **errCode=0**（新账号正常），题材端点仍 **errCode=9** → 限流**与账号无关**，是服务/IP 级短时窗口 |
| 单轮 3 次调用（间隔 5s） | 全部成功 → 限流阈值约「数分钟内 ~3-5 次」，不是「每天几次」 |
| **换出口 IP**（103.172.182.27）后单发 | 仍 errCode=9 → 非 IP 维度 |
| 换新铸 token（同一分钟内新铸两次） | 仍 errCode=9 → 非 token 新鲜度维度 |
| 整个 app 接口组的无关端点（`/config/one`）+ 两份不同 session（新账号 / 静态旧 session） | **全部 errCode=9** → 不是账号权限、不是单端点额度，是整个 `/jystock-app` 服务组的间歇限流 |
| 同分钟内两连发 `ai/industry/list` | **第 1 次 9，第 2 次成功返回 730 节点** → 间歇性（非持久封锁），与 web 端点 `/action/*` 完全独立 |
| 服务端“成功但空” | 限流期间会返回 **`errCode=0` 但 `data` 空**（2026-10-20 15:45 调度采集 industry `fetched=0` 却 `ok=true`） |

因此采集层的硬性纪律（已实现 + 测试锁定）：

1. **串行 + 源间间隔 20s**（`INTER_CALL_DELAY_SECONDS`）：单轮 3 次摊开 ≈40s，避开"数分钟 3-5 次"阈值；
2. **限流退避重试 1 次 / 60s**（`RATE_LIMIT_MAX_RETRIES` / `RATE_LIMIT_RETRY_SLEEP_SECONDS`）：
   最坏 3×(20+60)=240s < 调度超时 300s（`_THEME_COLLECT_TIMEOUT_SECONDS`）；
3. **计数落地**（`jiuyan_api_calls`，`_id={fetchDate}`）：失败的请求同样计数（服务端额度已扣），
   当日计数进 `jiuyanTheme` 状态，`callsUsedToday` 可查；
4. **每日调用护栏** `JIUYAN_THEME_DAILY_CALL_BUDGET`（默认 12，防失控；**不是**日额度断言），
   超出即跳过该源并在结果里 `skippedByBudget` 明示（不静默空跑）；
5. **分源调度**：盘前 08:45 只取事件日历（`timeline_news,timeline_list`），收盘后 16:10 只刷新
   板块催化正文（`ai_industry`）→ 每日 3 次调用（原设计 6 次）；
6. **人工探测必须单发**：本轮教训就是调研期连发探测把限流窗口打满，导致当天后续采集全灭；
7. **空载荷=降级，不是成功**（`emptySources` + `degraded: "<源>: 空载荷（errCode=0 但 0 条…）"`）：
   限流期间服务端会回 `errCode=0` + 空 `data`，若当成功就会把"限流"写成"今天没题材"（§4.0 禁止）；
   本次由此发现并修复了一个真实缺陷（15:45 调度采集 industry `fetched=0` 但 `ok=true`）；
8. **调度在限流期间的自我修复路径**：单轮失败只记 `jiuyanTheme` 状态（不阻断异动采集/打标），
   同日下一个槽位或人工 CLI 重跑即可补齐；采集写入是幂等的（`contentChanged=0` 实测）。

**仍未定（未证实，不得当结论）**：`timeline/list` 的**第 2 页**（`{"start": 2, ...}`）是否可取。
两次单发探测都撞在限流窗口内（对照组已知可行形状也失败=限流，非参数问题），故**未验证**。
可取 → 可回补更早事件（离线重放样本更多）；不可取 → 事件语料只有首屏窗口
（过去 ≈2 周 + 未来 ≈2 周），题材层只能**向前**积累样本。留作冷却后单发探测项。

**预算包络（用户 2026-11-11 批准「A+B+C 都修，补跑 pool 池龙虎榜数据」）**：每 pending 日
≤1 个日包络（2026-11-11 实测：22 doc/日 ≈112k tokens，input+output；旧 ≈29k 为 13 龙头
旧口径已作废）；探针缺席零消耗；主榜晚于 21:30

### 5.2 仍缺什么（不自欺）

| 缺项 | 影响 | 处理 |
| --- | --- | --- |
| 产业树 `content` 是"最近一次催化"的**单条摘要**，日期写在句子里，无结构化事件类型 | 无法直接统计"催化类型分布" | 允许；能量化的已有 `contentChangedDate`（今日新增催化检测） |

## 6. 验收门槛（预登记要点）

   **HTTP 开火路径补充登记**（2026-10-20 review）：`POST /api/hotlist-jev/theme-leaders/rerun`

## 14. 题集 v5：三层判断重构（题材深度 → 延续性 → 概率 → 空间；2026-10-23 用户裁决，当日落地）
