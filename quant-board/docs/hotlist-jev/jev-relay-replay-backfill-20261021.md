## 2. 大盘指数回填（可补部分）

- 数据源对账（2026-10-21）：本地 vipdoc 七指数日线（sh000001/sh000300/sh000905/sh000852/
  sh000688/sz399001/sz399006）与线上 mootdx `index_bars` 逐点一致（10-19 收盘七指数全部 OK）。
- 写入语义（沿 `backfill_slot_pctchange` 先例：provenance + 幂等 + `--apply` 门）：
  - 原生 `changePct`（10-16 起主 4 指数 12 槽）→ **跳过，永不覆盖**；
  - 原条目只有 `change` 点位 → 保留点位，补 `changePct` + `src`；
  - 条目/indexExtra 缺失 → 创建 `{"changePct": x, "src": SOURCE}`；
  - 缺当日/前收棒 → 线上兜底；双源全缺 → fail-visible 不补 0（本轮实测 0 条）。
- 显示端（`jev_relay_index.market_index_line._one`）：回填值带「（日线回填）」标注，
  原生帧值无标注——**不把重算值伪装成 15:00 实采**。
- 实测（`--apply` 后只读复核）：
  - 833 槽 = 119 日 × 7 全满（12 原生 + 821 回填）；幂等重跑 0 新写；
  - 09-01 → 七指数全值（原「该日未采集」）；10-20 → 深成 −0.14%/创业板指 −0.26%/科创50 +1.00%
    （用户 10-20 语料中三个「缺失」槽位已补齐）。
- 与帧点位的关系：历史帧 `change` 点位与日线重算存在不一致（如 10-19 帧 change=0.731 vs
  日线 +14.64 点，帧侧疑似错值——2026-10-16 假暴跌事故同源问题）。回填 pct 来自独立日线源、
  非点位换算，两者并存于 entry，显示以 pct 为准且带标注。

## 3. 对 v7 重放的影响（判据零改动）

- 重放语料的大盘指数行从大面积「缺失/该日未采集」变为七指数全值（回填值带口径标注）；
  `relay_index` 判据的「与大盘热度不必同幅」对照锚、`relay_phase` 的 broad_market 供给
  在历史样本上首次成立。
- 判据/题目集/分位口径零改动；重放语料与原运行语料的差异仅限此前缺失的槽位（补采后有值），
  复盘对比时应把「大盘指数行口径变化」计入语料代际注记。
- 4~5 月起点缺口（money_hist/韭研池）与 v5 全量重放口径一致，重放报告如实注记即可。
