## 2. 口径裁决（五项，开火后按此执行）

1. **连板高度单一事实源 = 真连板**（今日起往前连续封板交易日数）。新增
   `jiuyan_streak_map()`，复用 `jiuyan_consecutive_streaks:363` 算法（quotes-review 同款，
   纯 MongoDB 可回放）。取数规则：num「N天M板」**N==M → 韭研自证纯连板，streak=M（不回溯）**；
   **N>M → 走封板链回溯**得真连板，回溯撞 THS 炸板池缺失日 → None 不可算，不入桶、
   叙事披露，**不按 M 伪算**；num=None → 韭研首板口径记 1 板，昨日已在池的漏标股不计桶
   （沿用 `_dayUnmarkedPrev` 披露）。
2. **区间高度 M / 跨度 N 不退场，全部降级为区间标注**：龙序与龙头选择仍按 M
   （14天10板 本就是该板块最显高位股，用户明示龙一=新华文轩显示 14天10板），
   但文案必须同时给真连板数；「连板中/最高板/梯队分布/轨迹/三日链」等连板语义一律真连板。
3. **跌停源 = 东财跌停池（主）+ 全市场行情快照（兜底）双源**（上游选型全过程：
   ① 东财 push2ex 跌停池 `getTopicDTPool` 有 30 日客户端窗口且当时连打即封 IP →
   ② 用户裁决改同花顺 → ③ 同花顺 dataapi 无跌停池（`limit_down/limit_down` 实测 404，
   只有大面池）→ ④ 落定既有全市场行情快照（当日懒加载）→ **⑤ 2026-10-16 复核发现东财
   已恢复可达（VPN 下 HTTP 200、10-15 实测 tc=26 与审计 ground truth 一致），用户裁决
   改双源：东财主 + 快照兜底**）。
   - **主源 东财跌停池**：`https://push2ex.eastmoney.com/getTopicDTPool`，有历史
     （近 30 自然日窗口）、权威、与涨停/炸板池同族同口径。**不走 akshare**：
     `stock_zt_pool_dtgc_em` 内部是裸 `requests.get`（无节流/无 Referer/无会话复用），
     违反 skills/a-stock-data「东财防封」铁律（2026-06-30 实测：1 小时 45000 请求不走
     限流 → push2/push2his 全系列断连、IP 级封禁 20+ 小时）。本项目直连端点并套用
     `eastmoney_fund_provider` 同款纪律：串行最小间隔 1.5s+随机抖动、Keep-Alive 连接
     复用、UA+Referer 注入、429/403 立即 30 分钟冷却且**绝不重试**、backfill 连续 3 次
     失败熔断。
   - **兜底 行情快照**：`MarketQuotesCache` 的 Redis 共享层（腾讯源 ~5500 行 f3=涨跌幅%），
     判定走 `core/limit_rules.is_limit_down_pct`（与 dieban_count 同一条权威线，不写第二份
     阈值副本）。无上游 IP 风险，但只服务「当日」。
   - **末位降级 采集池口径**（250 只），叙事内显式标注「全市场源缺失」。
   - **EM 窗口边界**：`date < 今天-30 自然日` 直接判不可用且不外呼。EM 对窗口外日期只返
     0 行，与「当日真的 0 家」在响应上无法区分——把窗口外伪成 0 家会成片污染分位数
     （AGENTS §4.0：「取不到」与「真的 0」是两件事）。窗口内返空池 = 合法 0。
   - **同源采样**：分位历史必须与当日同源（em_pool / quotes_snapshot / pool_rows 三家
     口径不同，混采污染分位）；`reference_counts()` 一次 find 批量读，禁逐日连发。
   - **实时口径边界**：快照 TTL 300s、只服务「当日」叙事，且限 15:05 收盘截点后读取
     （盘中值落库会被后续叙事当收盘数复用）；历史日不读快照。
   - 涨停/炸板家数不动（THS 帧池双源已一致）。
4. **炸板率双口径**：曾封后开板 7/43=16.3% ｜ 触板未封 13/49=26.5%（含冲刺 6 家）；
   补烂板 15 家（帧 `sealQuality` 现成）。
5. **帧 `continuousBoards.maxBoard` 契约不动**（方向 v4/vote pilot 另有消费，独立轨道）；
   题目集判据零改动（`ladder_health` 判据明写「以叙事给出数据为准，勿心算」，
   语料修正即判据输入自愈）。

## 5b. 2026-10-16 盘后复核新增（停牌不算断板，跑完 10-16 端到端才发现）

10-16 盘后链实跑发现 §2.1 的真连板实现还有一个**反向病灶：停牌日被当成断板日**——
与用户最初报的「中间断板的股票计入了连板统计」同族，方向相反。

| 语料现值（10-16 首跑） | 实证 | 根因 |
|---|---|---|
| 最高 **4 板**（6 分位） | **11 板**（100 分位） | `jiuyan_consecutive_streaks:450` 把「昨日不在封板池」一律当断板 break；600825 10-13/14/15 上交所停牌（TDX 日线无棒），韭研/THS 池回溯里停牌与炸板完全同形 |
| 梯队 一板58/二板3/三板+2 | **57/3/3** | 同上，600825 被留在一板桶 |
| 首板占比 92%（58/63） | **90.5%**（57/63） | 同上 |
| `ladder_health` **pyramid**（0.82） | **inverted**（0.73） | 二板/三板+ 由 1.5 变 1.0，触发判据「三板+/二板 ≥ 1 高度集中在少数高位股（孤板/妖股结构）」 |
| 龙头档案头行「当前连板**1**板」 | **11 板** | 同上；板序行却写「当前连板 10」（另一处缺陷，见下）——同段自相矛盾，审计问题 #8 同族 |
| 近20日锚「最高板峰值 10 板（10-12）」 | **11 板（10-16）** | `narrative_context_lines` 用 `trading_dates_before(20)` 严格早于当日，今日创新高时锚显示旧峰值，与事实行「最高 11 板（100 分位）」矛盾 |

600825 事实链（TDX 200 根全量日线，非节假日缺口只有两段）：09-07~09-18 停牌 10 个
交易日（韭研解析显示 09-18 盘后披露重大资产重组）→ 09-21 起 10 个连续一字板 →
10-13~10-15 停牌 3 个交易日 → 10-16 复牌再封一字板。11 个 +10.0% 收盘全部落在连续
交易日上，韭研 `14天11板`（N=14 含停牌日、M=11 只数真实封板日）与之完全吻合。

**口径裁决（用户 2026-10-16）**：停牌日不是交易日，不构成断板，**跳过续算**。

**实现**（详见 design doc §9.1 决策表）：池权威 + TDX 日线补洞。日线是区分停牌/断板的
唯一信号；回溯窗由 max(M) 改固定 60 个交易日（停牌日不推进连板数，600825 M=11 实需
回溯 14 日，按 M 定窗会把链起点截窗外）；补「炸板池缺失日由该股日线补证」一路
（600825 链上的 09-23 正是缺失日，只靠池会整链不可验）；TDX 不可用不让步到「当停牌」。
板序行连板数不再被展示窗口截断（窗口内全 ● 时继续往前数并披露「连板延伸至窗口外」）。

**附带发现（非本次引入，列披露）**：10-16 存在 15:30 daily 帧（zt=60/failed=48/
rushing=15/rotten=16）与 15:00 half_hour 帧（59/49/14/14）差 1 只，所有消费方硬编码
`type=half_hour, slotTime=15:00`，叙事永不用最末帧；10-15 两帧一致（36/36），属既有
设计选择而非回归。另：920xxx 北交所 TDX 日线不覆盖（实测无棒）、002860 有 09-22~10-13
十日无棒（炸板股，streak 本就 None，无数值影响）。

**10-16 两篇 doc 已按裁决 `--force` 重跑**（新增单股重跑入口 `--codes`）：
relayIndex 26.8→30.0、`ladderHealth` pyramid→**inverted**、leaderStrength 77.1→86.7，
phase/momentum/money/theme 四判定不变；600825 打标标签分类未变（ma_restructure/continuing）。
其余 100 篇 10-16 打标的弹药首行仍带旧梯队/最高板（≈35.6 万 tokens/日），是否重跑另行记账。
