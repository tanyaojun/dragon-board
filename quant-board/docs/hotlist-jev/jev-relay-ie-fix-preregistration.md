# relay IE 读口径修复预注册（v5，2026-10-17）

> 触发：诊断文档 `jev-relay-insufficient-evidence-attribution.md` 记录的四批 IE（相位 14 / 边际 8 /
> 梯队 3 / 钱效 42）归因结论 + 用户 2026-10-17 指令「请修复」。
> 本文是**执行前契约**：范围、决策点、影响面、验收、预算、回退。范围是「读口径与展示」修复，
> **不含**采集层回补（不可行）与判据重设计。

## 1. 背景（一句话）

四批 IE 的根因全在**原料缺口**（16 天旧采集 schema 的炸板池只有家数 / 3 天 15:00 帧未采 /
TDX 60 棒窗回放限制），但**读口径把「部分缺失」放大成「整段没有」**：炸板面整段不可算、
梯队整段缺失、钱效用 n=1 的「中位」充数、覆盖不足没有结构化标记。修的是放大环节（AGENTS §4.0）。

## 2. 改动清单

### 2.1 F1 炸板池旧 schema 家数级降级（`jev_label_jiuyan._ths_failed_counts` + `jev_relay_index.zhaban_face_line`）

- 新增 `_ths_failed_counts(db, date, dataset_id) -> (counts, found)`：读旧形态
  `limitSummary.thsPools.poolCounts`（`failed/rushing/drawdown`）+ `maxDrawdown/avgDrawdown`。
- `zhaban_face_line` 在 `_ths_failed_items` found=False 时回退家数级渲染（**不整段丢弃**）：
  `今日炸板面（家数口径·旧采集 schema：仅家数可算，个股级子项不可算）：炸板 N 家；冲刺未封 N 家；
  涨停股回撤榜 N 家（最大/均值回撤）；较昨日：炸板 a→b 家（±d）· 反复开板 不可算；分位不可算（历史含旧 schema 日）`
- **口径纪律（D1）**：跨 schema 的**家数级**对比允许（同字段语义：THS `failed` 家数），
  但必须带「家数口径·含旧采集 schema 日」标注；**个股级子项绝不跨 schema 编造**。
- **禁止**：用 `snapshot_records.payload.limitSummary.zhaban.count`（前端口径）冒充 THS `failed`。

### 2.2 F3 梯队字段级降级（`jev_relay_index.ladder_structure_line`）

- `market_metrics` 返回 None / ladder 空时，回退 `_jiuyan_ladder`（**不依赖 15:00 帧**）出桶，
  并沿用既有来源披露（`jiuyan_touch` → 「THS炸板池缺失，梯队按触板口径」）。
- 不改 `market_metrics` 的 None 契约（消费方 6 处，改契约面过大）；**D3 默认选最小改动面**。
- 连带：`梯队结构量化` 行在 3 个无帧日恢复出数；`盘面事实` 行仍 fail-visible（涨停家数确属不可得）。

### 2.3 F4 断板/溢价最小样本门槛（`jev_relay_index`）

- 门槛（**D2 默认**）：`covered ≥ 5` **且** `covered/n ≥ 20%` 才输出中位；否则改写
  `断板 N 只：样本不足（TDX 覆盖 k/n，门槛 ≥5 只且 ≥20%），今日表现不可作钱效依据`（**不输出伪精度中位**）。
  绝对门槛不可省：07-06 的 `1/1`=100% 会漏过纯比例规则。
- 同门槛用于：断板统计、隔日溢价、较昨日断板对比、三日链内同名统计。
- `relay_money_effect` instructions 增一句：样本不足/覆盖过低的中位数不得作为钱效依据（**判据显式化**）。

### 2.4 F2 `anchorGaps` 结构化落库 + 前端徽标

- 新增纯函数 `anchor_gaps(narrative) -> list[str]`（扫标准缺位标记，不改打分）：
  `炸板面` / `炸板面个股级` / `三日链` / `梯队` / `断板钱效` / `盘面事实`。
- relay 文档新增字段 `anchorGaps`（附列，API 追加字段，合同向后兼容）。
- relay_page 行首日期格加「锚缺位」chip（hover 显示明细）；图例补一句说明。

### 2.5 F5 回放长窗机制（**D5 默认只实现机制、不启用**）

- `_daily_bars` 支持 `JEV_BARS_OFFSET`（默认 60 = 生产不变；缓存键含 offset）。
- 早期 42 天钱效/30 天连板高度要真正可算须**另立重放裁决**（会改早期断板口径与 §8 毒带读数）。

### 2.6 版本

`QUESTION_SET_VERSION_RELAY` **v4 → v5**（叙事变更必须可识别；v4 文档保留，混版由前端 badge 呈现）。

### 2.7 F6 叙事可复现性修复（执行中发现；不做则重判输入不可复现）

- `theme_ladder_lines` 的「驱动主类」原为 `max(set(drivers), key=drivers.count)`：`set` 迭代序受
  `PYTHONHASHSEED` 影响，**计数并列时跨进程漂移**——实测同数据两次独立进程构建 2026-09-07 叙事
  hash 不同（`383b870a` vs `46367a66`）。
- 改 `sorted(set(drivers), key=lambda x: (-drivers.count(x), x))[0]`（同数按名称升序）。
  已验证：两个独立进程对 09-07/10-16/06-24 的 hash 完全一致。
- 影响：v4 存量系列中 **16 天**叙事与现行代码不可复现（旧随机取值）；重判时一并修正。

## 5. 验收标准

1. 全库 108 天叙事 diff 清单 == 预期集合（§3），无意外天数变化。
2. 3 个无帧日梯队行出数且带触板口径披露（07-06 期望 `one 76 / two 8 / three 3 / four 4 / high 5`）。
3. 16 个旧 schema 日炸板面行出家数口径文本（08-24 期望 `炸板 17 家`、`冲刺未封 14 家`、`回撤榜 9 家`）。
4. 8 个低覆盖日断板/溢价行改「样本不足」，全文不再出现 `TDX 覆盖 1/` 形态的中位句。
5. `anchorGaps` 落库（新判定日）+ API 返回 + 前端可见；`questionSetVersion=v5`。
6. 回归：全库 pytest 全绿；relay 相关测试全绿；`--collect-only` 无 import 破坏；relay_page 内联 JS 通过 `node --check`。
7. 干跑（零调用）复核：10-16 / 08-24 / 07-16 / 07-06 四日叙事人工读一遍。
